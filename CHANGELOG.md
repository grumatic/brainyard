# Changelog

All notable changes to Brainyard's public distribution are documented here. Versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **`/copy` — put the last answer on the clipboard, without the rendering.** Mouse selection is owned by the terminal, and the terminal selects screen *cells*: a drag over an answer picks up the box border, the four-space indent and the vertical rail, plus the hard line breaks our own word-wrap inserted at the pane width. None of that is in the answer; all of it lands in the paste. `/copy` copies the **source** instead — the raw model answer is stashed per session as it is emitted, before formatting touches it, and recorded even when the box is suppressed for an `acp-agent` turn. `/copy code [N]` hands back a fenced block with the fences and rail already gone, so it pastes into a file and runs.

  Mechanism order is about where the clipboard *is*, not what is fastest: tmux first, then OSC 52 when `SSH_TTY` says the session is remote, then a native `pbcopy`/`wl-copy`/`xclip`/`clip.exe`, then OSC 52 as a last resort. Native tools are preferred locally because they can be verified, but over SSH they would cheerfully succeed against the wrong machine and report success — so the remote check runs first. OSC 52 is also the only thing that works in the `--web` path, where the terminal is a browser tab. There is no reply channel on OSC 52, so a send over it says "sent … if your terminal supports it" and names the terminals that drop it silently, rather than presenting a guess as a fact. Two quiet failures are guarded: an empty payload *clears* the clipboard, so blank input is refused, and past the control-string cap terminals truncate rather than error, so oversized text is refused too.

- **`by run --config` — an EDN map of agent config overrides at launch.** Flags can only say what someone thought to add a flag for. `-p`/`-m` cover an ACP backend and model and stop exactly there, so a pin carrying `:env` (how an Opus 5 preset reaches a model the adapter does not advertise) could not be expressed on a command line at all, and the caller had to create a second session to apply it. `--config` takes any `config-schema` keys as an EDN map and seeds them as per-agent overrides for the session, so a launch can now say everything a running session could be configured to. It is applied last and wins over the equivalent flags: it exists to state what they cannot, and a flag that contradicts it is the vaguer of the two.

- **`by projects remove <slug>` — forget one registered project.** `prune` can only take every *missing* record at once. That cannot express "drop this one", and it cannot touch a project that still exists — a repo you have stopped working on has not stopped existing, so its row was permanent. `remove-project!` is the per-slug counterpart, built on the same guarded `delete-record-dir!`, and it deliberately does not require `:missing?`. It removes only the user-scope record dir; the project is never touched, and re-registering restores the same path-derived slug. The verb takes a slug rather than a path, because the slug is what `list` prints and what a UI already holds.

- **`by sessions list --all-projects` — answer for every project in one process, not one per project.** It walks the user-scope registry, reads each project's sessions, and tags every row with `project-slug`/`project-path`. Off by default, because widening the default scope would change what every existing call answers. This exists to collapse a fan-out rather than to add a view: a multi-project console polls liveness by shelling out once *per project* per tick — liveness is a lockfile plus a live pid, so a crashed host changes nothing on disk and no watch or cache can substitute for a fresh read — and what that fan-out costs is process startup. Only this side can amortize it; batching in the caller just renames the same N spawns. Registry entries whose directory is gone contribute nothing, and a project that fails to read yields no rows instead of aborting the listing, because a whole-machine query that dies on one stale row is worse than one that reports the other nine. `--tree` is ignored under it, since lineage is a within-project relation, and the table groups under a project header so two identically-labelled sessions in different repos don't render as duplicates.

- **`{:op :a2a …}` — A2A peer CRUD over the ask channel, without a turn.** The four `a2a$*` commands are tool-defs, so every route to them ran through the model: an external driver that already held a peer name and URL was paying an LLM to retype them into a tool call, and hoping the retyping was faithful. `peers-op` is the machine-facing face of the same commands — same `:enable-a2a` gate, same name regex, same per-session peer cap, same registry, no turn — exposed as `{:op :a2a :action …}` on the session ask socket and advertised in the session `:ops` metadata. Two asymmetries are deliberate, because this is an API: `:add` refuses a name that already exists and `:update` refuses one that does not, since a caller that believes it is creating a peer while actually replacing a colleague's has no way to notice; and `:update` is disconnect-then-connect, so a changed URL cannot leave the previous endpoint's skills registered under the same peer name. The registry is process-wide, so `:list` reports `:host-wide? true` rather than letting a caller assume otherwise.

- **The TUI negotiates grapheme width instead of assuming it** (`BY_GRAPHEME_WIDTH`, `:grapheme-width`, default `auto`). Terminals disagree about how wide a grapheme is, and the two regimes differ by up to **six columns on one glyph**: a ZWJ family emoji is 8 columns summed per codepoint, 2 columns clustered. `auto` asks the terminal via DECRQM (`CSI ? 2027 $ p`) and caches the answer in `~/.brainyard/terminal-caps.edn`, keyed by `TERM` + `TERM_PROGRAM` + version + tmux — `TERM` alone is useless, since every emulator claims `xterm-256color`. It caches because a terminal that does not know DECRQM replies with *nothing*, so the read is time-bounded and that timeout is then paid in full: ~500 ms on the native binary, roughly 4× its entire startup. tmux never answers for 2027, so `auto` skips the probe there — but no longer assumes the answer either. Measured by writing into a pane and reading `#{cursor_x}`, tmux 3.6a **clusters**, so inside tmux the answer comes from measuring tmux (a detached scratch session, tens of ms, re-measured when the tmux version changes). Every failure mode resolves to clustering off, so `auto` can only ever be as wrong as `off`. Default `auto` because 2027 is default-**on** in Windows Terminal, WezTerm, Ghostty, Contour and foot, where a per-codepoint default is actively wrong.

- **Soft newlines where the terminal owns line breaking.** A hard newline inserted to make text fit is permanent and lossy — the terminal cannot tell it from one the author wrote, so a copied answer comes back broken mid-sentence. In **inline** mode the terminal advances the cursor itself, so each paragraph is now emitted as one logical line and DECAWM wraps it; there is no box, because a right border must be padded to a width we chose, and choosing that width is exactly what soft wrapping hands away. **Fullscreen** keeps the hard wrap deliberately: it writes each scrollback entry to an absolutely-positioned row, and viewport offset, page scrolling and every live block's start index all count entries *as rows*, so one soft-wrapped entry would occupy two and shift everything below it cumulatively. Cursor-addressed rendering and terminal autowrap cannot both be in charge.

- **The model catalog refreshes itself from each provider — including a local Ollama server.** The catalog was hand-maintained and baked into the binary, and it drifted: one audit against the live provider APIs found three OpenAI ids that do not exist (`gpt-5.5-mini`, `o3-pro`, `o1-mini`), a retired Claude family still listed, the Claude 5 family missing, and models catalogued that this client cannot drive at all. Ollama was the worst case by construction — a baked list of locally-installed models is a guess about somebody else's machine. Now each configured provider's model-list endpoint is consulted (`/v1/models` for OpenAI-compatible providers including Ollama, the Models API for Anthropic, `ListFoundationModels` + `ListInferenceProfiles` for Bedrock), cached under `~/.brainyard/catalog/<provider>.edn`, and merged over the baked catalog.

  **What refreshes and what does not is the design.** A provider's list is not a catalog: `/v1/models` also returns embeddings, TTS and image models, Bedrock adds Titan embeddings and Stability image models, and OpenAI's `-pro` tier is chat-shaped but served only by `/v1/responses`. Nothing in any response says which entries a chat client can drive, or which reject `temperature` — both were established by probing. So the overlay carries **model ids only**; `:curated-rank`, `:description` and `:region` stay human. A refreshed model becomes usable and listed immediately but never enters the `/model` picker on its own, which is what keeps a `whisper-1` out of it.

  **`bb catalog:refresh`** is the maintainer counterpart, keeping the catalog *shipped in the binary* current between releases: it reports how the baked catalog differs from the live providers, and `--write` deletes entries a provider no longer serves. Additions are reported but never written — an entry earns a place only once a human gives it a rank and a description. The rewrite is surgical rather than a regenerate, because `providers.clj` carries comments recording which ids were probed and rejected and a pretty-printed regenerate would delete them, after which someone re-adds the models they warn about. Ids deliberately not catalogued (OpenAI's `-pro` tier, the `-codex` line) are now `excluded-model-patterns` **data** rather than a prose note: as a comment they were invisible to the tool, so the first live run proposed all 40 as new models and would have on every run after.

  Four safety rules, each guarding a quiet failure mode: a provider absent from the overlay passes through untouched (the offline, first-run and no-credentials path); an empty fetch is ignored rather than applied, so an outage cannot be read as "this provider serves nothing"; a region-scoped Bedrock fetch is **additive only**, because the catalog deliberately pins us-east-1-only models and retiring on absence would delete a working model on account of where the user was standing; and providers with no list endpoint (`claude-code`, `acp`, `apple-fm`, `free-llm`) cannot be overlaid at all. Refresh is gated by `:enable-catalog-refresh` (default true), runs on a daemon thread behind `:catalog-refresh-ttl-hours` (default 24, with a much shorter TTL derived for local servers), and never blocks startup. `by models --refresh` forces one; `by models --drift` reports what the providers changed, collapsing dated snapshots of models already known so the lines a human must act on are not buried.

- **`by projects prune` reclaims registry entries whose project directory no longer exists.** Until now the user-scope registry only ever grew: `list` tagged a vanished project `(missing)` and kept the row, and since the slug is path-derived, *moving* a repo orphaned its old entry rather than re-homing it — so every scratch dir, temp checkout and moved project left a permanent row with no way to remove it. Pruning stays **explicit and confirmed** rather than automatic, because `(missing)` is not proof a project is gone: an unmounted volume, a detached disk and a downed network share all report identically and come back, and reclaiming automatically would silently discard the user-scope folder of a project that still exists. `--yes` skips the prompt for scripting, `--json` reports the pruned records. The slug is untrusted on this path (it is read back off disk, not recomputed), so the delete accepts only a bare directory name and re-checks that the canonical target is a direct child of the registry root; a hostile or malformed record returns false instead of throwing, so it cannot abort a prune partway and leave the derived index describing directories that are already gone.

- **`:switch-session` over the ask socket — an external driver can move the focused tab.** The session-lifecycle verbs let one JVM host many sessions instead of one OS process each, but a driver could only create, close and rename them: `:new-session` deliberately does *not* move the local terminal's focus, on the grounds that a headless caller spawning a session shouldn't yank the tab out from under whoever is sitting at the keyboard. That left no way to move it *deliberately*. `{:op :switch-session :session-id "agt-…"}` is the explicit opt-in, the process-level counterpart to `/session switch`. Idempotent — targeting the already-active session reports `:already-active` and does nothing — and it repaints the status bar after switching, since swapping the tab otherwise leaves the chrome advertising the previous session's agent and model.

- **`:resume-session` over the ask socket — an existing session can be brought back *into* a running host.** The lifecycle verbs let one JVM host many sessions, but only new ones: a driver could add sessions to a host it was already talking to, and had to launch `by run --resume <id>` for one that already existed. That is not co-hosting — it starts a SECOND host in the same checkout, on a private tmux socket where nothing looking for the first can see it, and leaves the next create facing two hosts with no way to guess which was meant. `{:op :resume-session :session-id "agt-…" :label "…"}` closes it, restoring the session's history, agent type, label and acp pin from its own `meta.edn` exactly as `--resume` does; `:label` renames as it resumes.

  **What it refuses is the load-bearing part.** A session open in another live process holds that process's ownership lock and its `ask.sock`, and a second opener would clobber both while interleaving snapshots into one file — so the op refuses, naming the owning pid. The probe is PID-checked, so a lock left behind by a crashed process does not block a legitimate resume. A session already live in *this* host is not an error but the answer, reported as `:already-live` with its tab index — the caller asked for it to be hosted here and it is.

  One thing is deliberately **not** restored: the persisted `:model`/`:provider`. The default LM is process-global (so is the `/model` command that writes those keys), so applying it would move every co-hosted sibling onto the resumed session's model. It comes back as `:model` in the reply instead, for a caller that wants to decide. Like `:new-session`, it does not move the local terminal's focus; `:switch-session` remains the opt-in.

### Changed

- **The whole `by` CLI is now ten subcommands, and the docs describe them.** `projects` and `a2a` shipped in v0.6.0 but `docs/usage.md` still described eight, on an "v0.3.x line" banner, with 21 agents (there are 26) and no slash-command reference at all. Refreshed against `by --help`: every subcommand and flag, a `/copy`-through-`/quit` command table generated from the same registry the TUI's own `/help` reads, the session-channel op vocabulary (five documented, fourteen exist), and an environment-variable table whose opening sentence used to say `BY_*` was read by the wrapper and, in the next clause, by the binary.

- **An ACP turn gets an hour, and permissions go through the same gate as everything else.** `:acp-timeout-ms` moves from 10 minutes to 60: the cap is total wall clock for the turn rather than an idle timeout, so a coding backend legitimately working longer than ten minutes got no credit for being busy and was cut off mid-flight. Separately, the ACP permission callback resolved no policy at all — it prompted unconditionally, so a container session set to `:auto-approve` still blocked on every backend tool call and a `:deny-by-default` session still put the question on screen. It now branches on `resolve-permission-mode` like every other sensitive tool op, and only `:ask-each-time` reaches the interactive prompter. `:acp-permission-timeout-ms` is gone: `:permission-timeout-ms` (60 s) is now *the* prompt timeout, and a key two capabilities both read cannot be owned by either — so it sits with `:permission-mode` in the never-gateable ambient set.

- **A session label is required, and a rename writes both surfaces.** A rename is a two-surface write — the persisted label in `meta.edn` (what `by sessions list` and the resume picker show) and the live TUI tab — and the three surfaces that performed one disagreed about both halves. The label text is now required everywhere rather than being read as a request to clear: an omitted argument is far likelier to have gone missing (an unset shell variable, a dropped quote) than to have been left out on purpose, and silently wiping a session's name on that mistake is the wrong default. There is no clear verb anywhere; to drop a name, set a new one. `:rename-session` writes the persisted half itself rather than relying on whichever caller happened to invoke it, and reports `:live-tab` for whether a tab was actually relabelled — so a session hosted without a tab gets its durable rename instead of an error.

- **An `acp-agent` session remembers what it was connected to.** Resume restored the agent *type* from `meta.edn` but not its backend. The pin is a birth property — read once when the session opens — and it only ever arrived as a call argument, so nothing on disk remembered it: a session created as Sonnet came back on the project default, and an Opus 5 one lost the `:env` that makes that model reachable at all. The resumed session answered as something else, with nothing on screen to say so. Only an **explicit** pin is written; recording the resolved value would freeze every session onto whatever the default was the day it was made. `{:op :new-session}` now carries `:acp-backend`/`:acp-backend-opts` too — `create-session!` had always accepted them, but the op destructured only `:agent-id` and `:label` and dropped them, so an external driver could create `acp-agent` sessions but not choose what they connect to.

- **ACP turns record a trajectory, like every other agent already does.** The recorder lives in CoAct's turn epilogue, which an `acp-agent` never reaches — its whole tree is one ACP round-trip — so ACP sessions wrote no `trajectory.edn` at all, and every trajectory-shaped surface (analytics, the workspace's trajectory route, anything reading a session back) was empty for the one agent type whose transcript is produced in another process entirely. One record per prompt now, on the failure path too: "the backend died here, on this question" is exactly what a later reader needs.

- **Every repaint is presented as one frame, and the cursor lands only on the input line.** Repaints are sequences of cursor moves, and they went out with the cursor visible and nothing marking where a frame began — so a fast burst let the terminal present intermediate states: the cursor flashing at column 1 of the bottom row, or parked on the status line over text still being drawn. That is the flicker seen in both the xterm and the browser terminal, and it was renderer-independent because the cause sits upstream of the renderer. Write sites now wrap their body in synchronized output (DEC 2026) plus a cursor hide, restoring the cursor only when input is active.

### Fixed

- **A mistyped subcommand no longer boots a session named after the typo.** Any bare first argument that was not a known subcommand or a flag was taken as an agent-id, so `by sesions list` started a full interactive TUI, **persisted** it, and wrote an unresolvable `:defagent-id` into its `meta.edn` — after which the failure surfaced far from its cause, as a `⚠ agent 'sesions list' is no longer registered` notice at session creation and a `[persist] dropping unreadable :defagent-id` line behind it. A quoting mistake produced the same thing: `by "sessions list"` arrives as one argument. A bare token is now accepted only when it names a registered agent (the legacy `by coact-agent` form) or matches the strict `provider:model` shape; anything else exits 1 naming what it could not resolve, with a `did-you-mean` suggestion that falls back to the token's first word when the token carries whitespace. Only built-in agents can satisfy that gate, which is correct rather than a limitation — user-defined agents are registered by a loader that needs an agent instance for its dirs and so runs inside a turn, meaning a positional user-agent id could not reach one before this change either. The routing rules moved into a pure `normalize-dispatch-args`, testable without the command's `System/exit`.

- **The scrollback is re-wrapped when the terminal is resized.** `handle-resize!` updated every geometry field and then replayed the *same* rows into a terminal that was no longer that wide. Nothing in the codebase touches DECAWM, so autowrap is on and the overflow was silent: each row wrapped onto the row below, the next row's `erase-line` wiped the spill, and the tail of every line disappeared — on the bottom region row it scrolled the DECSTBM region instead, shifting every absolutely-addressed row out from under the layout's model of where it was. Each emit now records **how to render itself at a width**, and a resize re-renders all of it, recomputing every live block's start index from the new row counts. The scroll position gets the same treatment, since the viewport offset counts *rows* back from the tail and the same number lands on different text after a rewrap. Live blocks needed this more than ordinary output, not less: a block self-corrects on its next tick while it is live, but the moment it freezes it keeps whatever width it was last wrapped at, forever. Several formatters had no width to reflow *to* — the welcome banner sized its box to its content, the next-prompt hint truncated at 200 chars (a content cap, not a width), and the permission prompts never wrapped their question at all — so they overflowed a narrow pane at launch, not just after a resize. The permission case was more than cosmetic: rows too wide are clipped at paint time, so a long path meant approving something you could not fully read.

- **Column budgets are enforced in columns, not characters.** A budget derived from `cols` and then enforced with `count` — UTF-16 code units — is wrong for anything but ASCII, and it was doing that on the input-bar tip, the autocomplete menu description, task activity and output lines, sub-agent activity, the tab strip and the feature table. Measured with CJK content, a task activity line budgeted at 80 columns rendered 126, at 40 rendered 71, and at 20 rendered 31 — over budget at every width, on precisely the lines carrying content nobody controls: a task name the user chose and task output that is whatever bytes a subprocess printed. With emoji the cut landed on a lone high surrogate. The help tip was worse than merely wrong: its flat cap of 72 ignored the pane entirely, so a 200-column terminal cut a suggestion for no reason while a 50-column one relied on the input row to cut it a second time — that outer clamp was silently doing all the work while the inner one corrupted the text on its way through. Writing the test surfaced a second bug: the variable part's budget was floored at 1, so when the prefix alone spent the whole budget the line came out one column over, and one column is all it takes to wrap. Content caps for LLM payloads, trajectories and logs are deliberately **not** swept — chars are the right unit there.

- **A timed-out ACP turn is cancelled, and says why it was cut off.** Two things happened when `:acp-timeout-ms` ran out: the turn ended with the bare text "ACP error: ACP await timeout", which names an exception and nothing anyone can act on, and the backend was simply abandoned — still working, still billing, still streaming updates into a turn that had been closed. The timeout is now its own outcome rather than a generic failure: the stop reason and trajectory `:terminated-by` are `"timeout"` rather than `"error"`, and the answer names the cap that cut it, whether the cancel went out, and the knob that changes it.

- **An ACP tool result reads as output, not as wire.** The result reached the TUI as the raw `ToolCallContent` vector, so the Result box rendered the envelope where the tool output belongs (`content: [{:type "content", :content {:type "text", :text "total 48\n…"}}]`). The failure path was worse — the whole map went through `pr-str` into the red Error box, so the preview showed `[{:type "content", :cont` instead of the message — and a diff rendered as one line of escaped whole-file text, while the result-size count included the envelope plus a duplicate of the output, overstating every result.

- **Two `by` processes are two A2A nodes.** The cycle guard identifies each node by a random UUID generated in a `defonce` initializer — and under GraalVM native-image a `defonce` runs at BUILD time, so that UUID was computed once during compilation and interned into the image heap as a constant. Every process launched from a given binary reported the same node id, which made brainyard-to-brainyard A2A impossible rather than merely mis-detected: the caller stamps its own id into the chain, the callee finds it already present, and refuses with `-32004 call cycle refused` on the very first hop, on loopback and across hosts alike. Only a non-brainyard peer, which sends no chain, could get through. The id is now minted lazily on first use. No unit test can catch a regression here — the defect is introduced by the compiler, not the code — so the guard lives in the build, as a `bin/smoke-native.sh` check that greps the image for a baked node UUID.

- **Every command writes an app log, and stopping it actually flushes.** The log was started only inside `cmd-ask` and `with-memory-manager`, so every other command ran unlogged — `by a2a serve` emitted its server-started event and every request event into a publisher that did not exist, which is why a running server had no audit trail at all. Hoisting it into the dispatcher turned up a second defect: `teardown-app-log!` never flushed, despite both call sites documenting it as one. mulog moves an event to disk over two asynchronous hops and a plain stop breaks both — it deregisters first, so whatever is still in the global buffer is never handed over, then dispatches its final write with `send-off`, which returns immediately, so a process exiting right after kills the JVM mid-action. The order has to be wait → stop → await. Cost is roughly 200 ms at exit, accepted deliberately in exchange for complete logs, including the detached `by memory reduce` child whose only durable audit trail is this log. Library warnings are routed into the same file on every command path rather than to logback's default console appender, which would otherwise print onto the screen the TUI is drawing.

- **Every log event names the process that emitted it.** Several `by` processes append to one `~/.brainyard/logs/agent-tui-app.log` at once — an interactive TUI, a detached consolidation, an A2A server, and every one-shot command — and no field said which of them wrote a line, so an interleaved log could not be attributed to a process at all. That is not academic: it invalidated a measurement in this very series, where a delta of new log lines attributed to one command was mostly other processes writing concurrently. The stamp is applied at **publish** time rather than from the global context, which is what lets it also reach events emitted while namespaces *load* — native-image evaluates build-time initializers but cannot perform a publish, so a publisher is guaranteed to run at runtime and has nothing to bake.

- **The build stopped shipping log lines inside the binary.** Top-level forms that self-wire hooks call mulog while loading their namespace, before any publisher is registered, and mulog holds such events in a global buffer deliberately so nothing emitted during startup is lost. Under native-image, namespace loading happens at BUILD time — so that buffer was non-empty exactly when the image heap was snapshotted, the events shipped inside the binary, and every launch republished them carrying the build machine's timestamp and flake id. The feature that protects startup logging on the JVM is therefore what leaked build residue into the native binary. It stayed invisible at a few hundred bytes per launch and became a 50 MB log once a desktop app started polling `by sessions list --live --json` about forty times a minute, each launch replaying the same records. Events that predate the process are now filtered out rather than the buffer being cleared: clearing looks equivalent but would discard a JVM process's own legitimate load-time events, and no event a process emits can predate its own start.

- **`aws/client` builds its own credential chain again.** aws-api removed the 0-arity `default-credentials-provider` — it now needs an http-client, because the container and instance-profile links reach IMDS over HTTP — so every caller of `create-client` that omitted a provider threw `ArityException`. The key is now omitted entirely rather than passing a separately-built provider, which would have spun up a second HTTP client purely for the IMDS lookups.

- **A `by` started from inside a Claude Code terminal can spawn an ACP backend.** It inherits `CLAUDECODE=1`, and `ProcessBuilder` hands the whole parent environment to the child, so every `claude-code` ACP backend died on spawn with "cannot be launched inside another Claude Code session". The guard is right about two interactive sessions sharing a terminal; an ACP backend is not that. The nested-session markers are stripped from the inherited environment before the launch spec's own `:env` is applied, so an explicitly-set marker still wins — only inheritance is refused.

- **A dead working directory no longer reports itself as a missing CLI.** `start-claude-process` built a bare `ProcessBuilder`, so the child inherited the JVM working directory — and a JVM whose cwd has been deleted or unmounted cannot spawn *any* child. The resulting `IOException` reads `Cannot run program "claude" (in directory "/gone")`, which matched both of this function's CLI-not-installed predicates, so a dead working directory was reported as "Claude CLI not found. Install Claude Code CLI first." — a confidently wrong diagnosis that sends the user to reinstall a CLI sitting right there, and never mentions the directory. The spawn directory now falls back to the temp dir when the cwd is gone, and a new catch branch keyed on "in directory" runs *before* the not-installed branches.

- **The first-party `:a2a/*` stream events are catalogued**, so their subscriber stops logging an `::unknown-event` WARN naming a first-party event as unknown on every process start. Nothing was broken by it — the bus fires any keyword, so remote artifacts were being persisted the whole time — but the omission cost `known-event?` the ability to advertise the family at all, and invited exactly the investigation it caused.

- **Releases are now verified after publishing, not just after staging.** v0.6.0 was published with a hand-written asset list that omitted the version-less `by.jar` alias — the copy that keeps `releases/latest/download/by.jar` (documented in `docs/build-and-deploy.md`) resolving. `SHA256SUMS` still listed it, so the documented stable-URL download 404'd and `shasum -c SHA256SUMS` exited 1 for everyone who verified their download, on a release whose binaries were otherwise fine. The missing asset has been uploaded, so v0.6.0 now verifies clean. Nothing in the build or staging step could catch this, because it happens after both: new `bin/release-verify.sh` re-downloads a published release and checks it against the manifest that shipped with it, failing on an asset that was checksummed but never uploaded or that uploaded corrupted (`--dir <path>` runs the same checks on a staging dir before publishing). `bin/release-stage.sh` now prints the exact `gh release create` command covering every staged file, so the asset list is never retyped.

### Internal

- **The silently-ignored ProcessBuilder hint came back, in the detached-consolidation spawn.** `aad4e98` fixed this shape in `terminal-caps` and its comment predicted the recurrence; `main.clj`'s `spawn-detached-reduce!` had carried the same `^java.util.List` on a **literal vector** since 2026-07-04. The reader attaches that as the vector's own metadata rather than as a compiler type hint, so the ctor stayed reflective while *looking* hinted — the failure mode being that nothing warns you the hint did nothing. Now `into-array` plus the array-class hint, matching `sh-tty`. The reflection ratchet drops 39 → 38.

  Nothing was broken in the meantime, because `reflect-config.json` carries a hand-written `java.lang.ProcessBuilder` `<init>(java.util.List)` entry that made the reflective call resolve under native-image. That entry **stays**: it has a second consumer with no hint to fix — `clj-sandbox` binds `java.lang.ProcessBuilder` into the SCI `:full` interop palette, and SCI resolves by reflection at runtime, so under the native binary only classes already in the reflection config resolve at all. Removing it would have broken `code$eval` interop under `:sandbox-interop :full`, a container-only path no smoke test exercises — a silent break traded for a cosmetic cleanup.

- **`bb reflect:check` run on its own reports against the *previous* AOT compile.** It answered "no new reflective sites" twice while an unhinted `ProcessBuilder` ctor existed; only `compile:ata` regenerates the warnings. A green `reflect:check` means nothing unless a compile ran first. Worth knowing alongside the fix itself: `^java.util.List` on a **literal vector** is silently ignored — the reader attaches it as the vector's metadata rather than as a compiler type hint — so the call stays reflective with no new warning to say so. The working form is `into-array` plus the array-class hint.

- **The iteration-block live ticker no longer races its own tests.** `start-iteration-block-ticker!` re-renders every non-`:done` block from a daemon thread once a second, while the tests install a *global* `with-redefs` on the render fn — so a ticker still alive from an earlier test called the test's own capture with a foreign key, and because the ticker only ever visits non-`:done` blocks the clobber always looked like a stage regression. It failed roughly one full-workspace run in six and was green in isolation. Fixed at the class level: the fixture now suppresses ticker startup for the duration of each test (nothing there asserts a ticker starts) and stops any inherited from an earlier namespace. `session.clj` gains `stop-iteration-block-ticker!`, mirroring the subagents and task-block ones — the iteration ticker was the only one of the three that could not be halted deterministically.

## [v0.6.0] — 2026-08-05

### Added

- **A2A (Agent2Agent) — Brainyard can now delegate to agents in other processes, and be delegated to by them.** Brainyard already had a well-fenced *in-process* agent-to-agent mechanism (`agent-registry$ask`, a reach policy, depth and cycle guards, an LRU cap) and two one-way bridges out: ACP, which is stdio-only, client-only and shaped for coding CLIs, and MCP, which carries *tools* rather than agents. Neither lets a `by` agent talk to an agent on another host or built on another framework, and nothing let an external orchestrator delegate *in*. A2A — the Linux Foundation standard, JSON-RPC 2.0 over HTTP with SSE — closes that gap in both directions. Three new components (`a2a` protocol core, `a2a-client`, `a2a-server`) plus runtime wiring; design in [`docs/design/a2a-design.md`](docs/design/a2a-design.md).
- **Remote peers are agent-registry entries, not a parallel vocabulary.** `a2a$connect` fetches a peer's Agent Card from `<url>/.well-known/agent-card.json`, negotiates the protocol version, and registers every skill it advertises as a callable agent `a2a$<peer>$<skill>`. From there a remote agent is asked with **exactly the same commands as a local one** — `agent-registry$ask` for follow-ups (which continue the peer's own conversation, so a second question lands in the same remote thread), `agent-registry$list`/`$detail` to inspect it, `agent-registry$close` to reclaim it — and it inherits the reach policy, the call-depth guard, LRU eviction and the parent-close cascade unchanged. This cost no new machinery: `ask` was already polymorphic at `proto/process`, so a `RemoteAgent` record carrying the same two atoms flows through every one of those call sites without modifying any of them. There is deliberately **no `a2a$ask`** — a second ask path would fork the reach policy, and the fork is the copy that forgets a rule. Long-running remote work rides the existing task manager as a `:a2a` job type, so `task$wait` / `task$cancel` / `task$detail` work on it; streamed output renders progressively in the TUI through the hooks that already exist, so there are no TUI changes at all. `a2a$list` / `a2a$card` / `a2a$disconnect` complete the connection surface, and **`a2a-agent`** is the conversational front door over them, adding zero new commands.
- **`by a2a serve` — exposing local agents to other agents.** Generates an Agent Card from the live roster and serves JSON-RPC plus SSE on the JDK's own HTTP server (no new dependency, and it ships inside the native binary rather than being exiled to a JVM-only base). **Inbound A2A executes prompts against your workspace with tools and disk access**, so the containment is explicit rather than implied: the whole feature is off by default (`:enable-a2a`), a bearer token is *required* to bind — there is no unauthenticated mode, because that is the flag that ends up set in production — the bind address defaults to loopback with a warning when it is widened, tokens are compared in constant time, and `:a2a-expose-skills` is an **empty allow-list** with no deny-list mode, so nothing is reachable until an operator names it. Unknown and unauthorized task ids return the same response, so the error channel cannot be used to enumerate what exists.
- **Cycle and depth detection that survives a network hop.** In-process, cycle detection is a dynamic binding; a dynamic binding does not cross a socket, so two Brainyard instances pointed at each other would recurse until something timed out — burning a real LLM turn on every hop. The call chain now travels in `Message.metadata` under namespaced keys and is checked *before* any work is done. Two details are load-bearing and both were got wrong first: the chain carries stable per-process **node** ids, because an instance has two unrelated names for itself (`main-agent/x` locally, a URL remotely) and an agent-scoped chain would compare the two and never match; and the **caller** appends itself rather than the callee, or a membership check would refuse the very first hop. Absent metadata — a non-Brainyard client, the common case — is not an error. This is a cooperation protocol between well-behaved peers, not a security control: a remote caller controls its own metadata, and authentication, the allow-list and the OS sandbox are what actually contain it.
- **Both A2A wire dialects are spoken, and negotiated.** A2A v1.0 did not extend v0.3 — it **replaced the JSON-RPC binding**. v0.3 is a hand-shaped JSON encoding; v1.0 is ProtoJSON over the protobuf model, differing on method names (`SendMessage`, not `message/send`), a required `A2A-Version: 1.0` header, enum spellings (`ROLE_USER`, `TASK_STATE_COMPLETED`), a `Part` with no `kind` discriminator, a result wrapped in `{"task": …}`, stream frames wrapped in `{"statusUpdate": …}`, and a `TaskStatusUpdateEvent` with no `final` field at all. A v0.3 client cannot call a v1.0 server. Brainyard now speaks both: the client picks per peer from its Agent Card, the server per request from the inbound header (falling back to the method name, which is unambiguous because the two vocabularies are disjoint), and a single Agent Card advertises **both** generations — they are different fields, so one card serves a client of either era with no negotiation and no second endpoint. `:a2a-dialect` (`:auto` | `:v0.3` | `:v1.0`) pins a peer that mis-advertises. One namespace, `a2a/core/dialect.clj`, knows a second dialect exists; everything else works on a single canonical form, so the event translator, the outcome normalizer and the agent-side service were untouched.
- **`bb a2a:interop` — an interoperability check against the official Python SDK.** Provisions the `a2aproject/a2a-samples` helloworld agent into a cached venv and drives brainyard's client through connect → agent card → `SendMessage` → `SendStreamingMessage`, asserting a real answer and a terminal stream descriptor. Deliberately outside `bb test` (it needs Python and, on first run, network) and it skips cleanly rather than failing when either is absent. It exists because **nothing else can catch a wire-dialect change**: brainyard shipped A2A speaking v0.3 while the ecosystem had already moved to v1.0, and the entire suite stayed green throughout, because fixtures encode what we already believe. Only an independent implementation disagrees with us.
- **Verified across processes, not just in a suite.** A `bb tui` JVM as client against a separate `by` process as server: card discovery, a real LLM answer returned across the wire, a follow-up continuing the same remote conversation, and the remote instance showing up in `agent-registry$list` as `:kind :remote` — plus the same protocol surface exercised against the shipped native binary. Two defects surfaced only there, both invisible to a green suite because every unit test had set the relevant state by hand: call depth was counted three times (so no remote call could succeed at all), and the streaming path never carried the peer's context id (so every follow-up silently started a fresh remote conversation). Both are fixed with regression tests. **Not implemented:** OAuth2 client authentication — bearer, HTTP basic and API key are supported, but `clj-oauth` has only interactive login flows, not the `client_credentials` grant server-to-server auth needs — and push notifications, which are declared unsupported and answer `UnsupportedOperationError`, the spec-correct reply for an optional method a server does not offer. Both are written up in the design doc rather than left to be rediscovered.
- **Every project gets a user-scope folder, keyed by a reversible slug.** Projects are registered under `~/.brainyard/projects/<slug>/`, giving user-scoped state *about* a project a home that is not the repo's own `<project>/.brainyard/` (which travels with the codebase). v1 stores **registry metadata only** — `project.edn` with the canonical path, name, git remote, and created/last-opened stamps; nothing moved out of project scope. The slug is `<sanitized-basename>-<8 hex of SHA-256(canonical path)>`, e.g. `brainyard-3f9a1c2d`: space-free, readable, stable (so registration is idempotent), and collision-free across two checkouts sharing a basename. Two decisions worth knowing: **slug → path is a lookup, not an algorithm** — it is recovered by reading `<slug>/project.edn`, because the tempting alternative of encoding the path by substituting separators (`/Users/me/my-app` → `-Users-me-my-app`) stops being reversible the moment a path segment contains the separator, and real paths do (`my-app` vs `my/app`); and **`index.edn` is a derived cache, never authority** — rebuilt by scanning the per-slug records, so concurrent `by` processes never contend and a torn index heals on the next refresh. Registration happens in `run-tui!` and `cmd-ask` only, always *after* `install-working-dir!` so `-C`/`BY_PROJECT_DIR` are in effect, and failure is swallowed — the registry must never block a session. Surfaced by `by projects list` / `by projects path <slug>`. Design in [`docs/design/project-registry.md`](docs/design/project-registry.md).
- **`by projects add` registers a project without booting a session.** The registry previously only gained entries as a side effect of `run-tui!` and `cmd-ask`, so anything wanting to offer "add an existing repo" — a desktop shell, an editor plugin, a setup script — had to start a whole agent just to record a path. The command is one call to the same idempotent `register-project!` those paths already use, so re-adding preserves `:created-at` and re-stamps `:last-opened-at`. It defaults to the effective working directory (a bare `by projects add` inside a repo registers that repo) and refuses a path that is not a directory rather than writing a permanently `(missing)` row.
- **`debug-agent` can now debug a running Brainyard from the shipped artifact, with no git checkout.** Three gaps closed. The created-hook **ensures the loopback nREPL server** itself rather than logging a warning and leaving the LLM to run the start-server lifecycle by hand; the agent declares `:config-extra {:nrepl-enabled? true :clj-backend :nrepl}` so it carries its own opt-in, and the hook re-asserts `:clj-backend` as a backstop because `setup-agent-by-id` merges caller options over `defagent` meta *shallowly* — a caller passing its own `:config-extra` would otherwise silently demote the agent to the SCI sandbox, where it answers confidently from an image it cannot see. New `config/resolve-clj-backend` demotes `:clj-backend :nrepl` to `:sandbox` unless the same agent also enables the channel, so one global value cannot move every coact-derived agent onto the full-trust backend. `BY_NREPL_ENABLED=false` remains the kill-switch, since env is the top precedence layer. **It refuses under native-image**, checking eval support *before* the already-running short-circuit — a GraalVM native `by` can open a socket and write a port file, producing a server that looks healthy while Clojure cannot compile a single form there; the refusal carries the remedy (`BY_JAR=1`). **`clj-nrepl add-classpath`** (gated to `debug-*`) adds roots to the live classpath, attaching to the *outermost* `DynamicClassLoader` rather than `RT/baseLoader`, because nREPL pushes a fresh loader per evaluation and a throwaway child is discarded when that eval returns. And **`materialize-sources`** extracts the 315 `ai/brainyard` `.clj` sources the uberjar already ships to `~/.brainyard/src/<build-version>`, leaving a populated destination alone (it may hold edits) unless `:force`. It deliberately does **not** add that tree to the classpath: delegation is parent-first, so the jar wins for a namespace it ships and `require :reload` would re-read the frozen copy while looking like it reloaded — edits are applied with `load-file` on an absolute path.
- **Registered tools are auto-bound into the live nREPL image (`:nrepl` backend).** `coact-init` builds one bindings map and uses it twice — injected into the SCI sandbox, and rendered by the system prompt as the Function Directory. On the `:nrepl` backend the Clojure fences route away from that sandbox to a bare socket eval where nothing was interned, so an agent was handed a catalog of callables that could not resolve, and the prompt then contradicted itself three ways. The bindings are now interned into a per-agent `by.tools.*` namespace, so the prompt and the runtime agree.
- **`:enable-tool-binding` (default true) makes tool discovery cheap.** An agent's declared `:agent-tools` roster buys exactly two things — the `### Agent Tools` prompt block and the `tools-fn-map` fast path in `call-tool` — and neither is needed to *call* a tool: `call-tool` falls through to the `!tool-defs` registry, which applies the same visibility check and the same `:agent.tool-use/pre` hook chain. The roster is documentation, not capability, and can now be turned off to reclaim the prompt space.
- **`:share-parent-session` models session-sharing subagents as a first-class kind.** A subagent used to mean exactly one thing: dispatched by a behavior tree, borrowing the parent's session, dying when it answers. ACP connections are the other kind — peers inside the user's own session — and were modelled by having *no parent*, which made them read as **roots** to everything asking "does this instance have a parent?": they clobbered the session's resume identity in `meta.edn`, passed the reach fences as roots, and fell through session-store defaulting. The hierarchy is now two orthogonal axes — **hierarchy** (exactly one root per agent-session; who owns per-session singleton behaviour and the persisted resume identity) and **dispatch** (who is talking to this instance) — which removes the per-`defagent` `:acp-agent` exception that patched the first symptom.
- **`by --version` names the exact commit it was built from.** `bb version:ata` previously stamped only `{:version "<git describe>"}`; it now writes `:version :sha :sha-short :branch :commit-time :dirty? :built-at`, each degrading to `"unknown"` when git is unavailable so clean tarball builds still work. `:version` stays the first key on one line, because `bin/release-stage.sh` awk-parses it out of that file.

### Fixed

- **The bash tool could hang indefinitely on a credential prompt — on five spawn paths, not one.** Closing the child's stdin stopped it reading the pipe but not opening `/dev/tty`: `ProcessBuilder` leaves the child attached to the JVM's controlling terminal, which exists whenever `by` runs from a real one, so `git` asking for a password, `sudo` and `ssh` went straight to the terminal and blocked. Three things compounded — the prompt goes to the tty so `:output` came back **empty** and the model got no hint why the call stalled, the timeout argument defaults to `nil` so the wait was unbounded, and detach only rescues the top level (calls from a subagent or inside a task context run synchronously). Commands are now re-exec'd in a **new session** with no controlling terminal, so `/dev/tty` fails `ENXIO` in milliseconds; `perl` is tried before `setsid` because util-linux `setsid` *forks* when its caller is already a process-group leader, which would let the parent exit while the real work ran on. A second hole remained after that: `git`/`ssh` spawn an **askpass** program, and a GUI one pops a dialog with no terminal involved at all — `GIT_ASKPASS`/`SSH_ASKPASS` are now pointed at `false` and `SSH_ASKPASS_REQUIRE=never` set. `credential.helper` is deliberately untouched, so silent keychain-backed auth keeps working; the two mechanisms had been conflated. The first fix landed on **one** spawn site while four others built the same argv by hand — the `:bash` task executor, the coact shell primitive, inline `run-script-block`, and the skills runner — each measurably still hanging under a real pty. `agent.core.proc` now owns the shared `sh-argv` / `harden-env!` / `shell-pb`, so a sixth spawn site inherits the protection instead of becoming a fifth copy of the bug.
- **One corrupt `meta.edn` broke session listing for an entire project.** A session whose meta held an unreadable keyword (a free-form prompt coerced to `:reply this: OK`) threw `Invalid token` and took down `by sessions list`, `/session list` and `discover-attach-target`. Reads now route through a single guarded `safe-read-meta` that never throws, and `save-meta!` sanitises identity keywords whose printed form embeds whitespace or an EDN delimiter, so an unreadable file can no longer be produced.
- **A reused pid could make a dead session look live.** `alive?` was a bare `ProcessHandle/of` presence check, but a pid is not a durable identity — when a host dies the OS may reissue it, and every session whose lockfile names that pid reads as owned again.
- **Usage-nudge hooks could be silently disarmed for the life of the JVM.** Registration sat behind a `defonce` latch, so once any caller invoked the public `reset-hooks!` the observers were gone for good and `ensure-global-hooks!` could never restore them. Replaced with a plain re-armable register that dedupes by handler id.
- **ACP model ids resolve by tier, and honor a global `:acp-backend-opts`.** `resolve-model-id` did a single OR-scan across `modelId`/`name`/`description`, so `"opus"` matched the *description* of the first entry and short-circuited before reaching the real `opus` entry. The stale `:stub` backend default on `acp-agent` is corrected, and a bare ACP error now surfaces the backend's stderr instead of hiding it.
- **A2A: warm contexts are closed on shutdown** rather than orphaning subprocesses, **call depth is counted once** rather than three times (which made every remote call fail), and the **streaming path carries the peer's context id**, so a follow-up continues the same remote conversation instead of silently starting a fresh one. JSON-RPC endpoints resolve from v1.0 `supportedInterfaces`.
- **Provider detection no longer throws on a nil or non-string model.** `get-provider-from-model` ran unguarded `String` interop, so `nil` raised an `NullPointerException` and a keyword raised a `ClassCastException` — opaque failures surfacing from deep inside `create-lm`. It also gained the missing bare-vendor `anthropic.` Bedrock prefix: every bare `anthropic.*` id had been depending on a catalog hit to route to `:bedrock`, and fell through to `:anthropic` once a retired entry was removed.
- **`clj-nrepl` bounds its TCP connect,** so an unreachable endpoint honors `:timeout-ms` instead of blocking.
- **Two A2A config keys were absent from the feature ledger,** leaving `:a2a-max-contexts` and `:a2a-context-ttl-ms` unclassified.

### Internal

- Polylith change detection restored, with fast targeted test runs; `smoke:ata` accepts an optional binary path.
- Shared `ai.brainyard.acp.core.env` extracted, duplicate `resolve-dirs` wrappers consolidated, and keyword env keys normalized in the stdio transport.

## [v0.5.1] — 2026-07-30

### Fixed

- **`acp-agent` failed on first use in every shipped binary.** Starting an ACP session (`/session new acp-agent claude-code sonnet`, or `by ask -a acp-agent`) exited immediately with `acp-agent needs ai.brainyard/acp-client on the classpath; could not resolve ai.brainyard.acp-client.interface/spawn!` — naming a dependency that was already declared and present. The classpath was never the problem. `acp_agent.clj` reached `acp-client` only through `requiring-resolve`, and Clojure's AOT compiler follows a static `:require` and nothing else, so the namespace was never compiled: the uberjar carried it as `.clj` source with **zero** `.class` entries, against 36 for a statically-required component. A GraalVM native image has no runtime Clojure compiler and so cannot load a namespace from source. Requiring it statically emits the classes (0 → 124) and fixes both the native binary and the `:acp` clj-llm provider, which shares the image. The soft-resolve had also hidden the dependency from static analysis — with the require made static, `poly check` immediately demanded that `agent-tui-app` declare `acp-client` and `acp`, so both are now project dependencies. As a side effect their six test namespaces now run in that project too (230 → 236 workspace-wide).
- **Every ACP turn then died on its first outbound message** with `java.lang.String cannot be cast to char[]`. `Writer` declares both `write(String)` and `write(char[])` at arity 1, so hinting the receiver as `^OutputStreamWriter` does not disambiguate — the argument type does, and the JSON-RPC encoder's return value was unhinted, leaving the call to compile to reflection. On the JVM the reflector picks `write(String)` from the actual argument, which is why this stayed invisible for the life of the code including live multi-turn ACP verification; in a native image the same call binds `write(char[])` and throws on the cast. Fixed with a `^String` hint; `acp` and `acp-client` are now both reflection-warning clean.

### Notes

- Both defects were **native-image-only**, which is why ACP had passed repeated live end-to-end verification while never once working in a binary users install: that verification ran through `bb tui:acp` on the JVM, where runtime source loading and reflective overload resolution both behave differently. `acp-agent` has been advertised in `by agents` since v0.2.0 and has never functioned in a shipped release until now.

## [v0.5.0] — 2026-07-30

### Added

- **A feature registry over the config schema — 43 features across 10 families, with `/feature` and `feature$*` as the capability view.** `config-schema` is a flat map of 151 keys: it knew what each key *is* but nothing knew what each key *belongs to*, so membership existed only as `;; ---` comments that nothing could query and no test could enforce. A new registry (`core/feature.clj`) is a view over that schema — storage, precedence, and the config-agent allowlist are untouched — partitioning every key into gates, knobs, presentation, and ambient, with the partition enforced by a test invariant: add a schema key without classifying it and `bb test` fails. Resolution applies declared `:implies` and `:requires` on top of the raw gate, so **a gate set `true` can still resolve `off`** when a requirement is unmet (fail-safe), and `:requires-partial` marks a feature `:degraded` without disabling it. One chokepoint (`on?` / `off-reason`) replaces the previously scattered gate reads, which is what makes the declared dependencies apply everywhere rather than in a handful of places. **`feature$explain`** is the surface that earns its place: it reports the resolved state, the gate and the precedence layer that supplied it, what implied it, which requirements are unmet, whether a restart is owed, and every associated knob with its value, default, and source — previously that answer meant reading six files. **`feature$list`** summarises the ten families reflecting *resolved* state (so `capture=false` visibly prunes the features that require it) and expands one family on request; **`feature$set`** writes through the normal config path. **`/feature`** is the same data in the TUI — roughly ten rows at the first level, annotating only the surprising states (implied-by, unmet requirement, degraded, restart-pending, ungated), each row carrying the registry's own `:doc` so the list says what you would be turning off. `config-agent` gains a section on when to reach for `feature$*` versus `agent-runtime$config`, and the setup wizard gains a Features step.
- **Family master switches, `BY_FEATURES`, and feature profiles — three ways to steer capability in bulk.** Nine boolean keys, one per family, are ANDed into that family's gated features, so `/feature memory off` works as a kill-switch (only an explicit `false` disables — a `nil` read defers to the schema default, which is what keeps a partial config view from silently switching a family off). **`BY_FEATURES="+memory.graph,-automation.reactions"`** overrides any set of gates from one environment variable, covering the 14 gates that had no env var of their own; a specific `BY_ENABLE_*` still beats the bulk list, an unresolvable token is dropped rather than thrown, and the list cannot defeat a declared `:requires`. **`BY_PROFILE=minimal`** (or `:feature-profile` in `.brainyard/config.edn`) sets a baseline: `minimal` turns off everything that spends an LLM call or runs work off-turn, `full` turns on graph memory, self-improvement and mid-turn recall, and `standard` is empty on purpose so the default profile changes nothing. A profile can raise or lower the baseline for keys you have not set and **can never override one you have** — verified against real config files rather than asserted.
- **User-defined state machines — a stateful reactor over the same event bus (`fsm$*`).** Where a reaction is a flat `event → action` rule, a state machine is a durable, per-session states-and-transitions graph: a definition store under `.brainyard/fsm/<id>/machine.edn` plus per-session runtime state, with declarative guards (`:event/match`, `:context/=`/`gte`/`all`/`any`, `:agent/idle?`/`running?`) and actions that reuse the reactor's sinks plus `:assign` and `:emit`. Transitions fire lifecycle events (`:fsm/transition`, `:fsm/entered`, `:fsm/final`) back onto the bus. Beyond event-driven steps, a state can carry **`:always`** (eventless, evaluated on each scheduler tick, chaining within a tick and bounded) and **`:after`** (timed, via an `:elapsed/gte` guard over a persisted `:entered-at`). A **`## State Machines`** user-context section surfaces each machine's current state, context, and last transition to the agent every turn, and an `ask.sock :op :fsm-status` verb exposes the same to external readers. An opt-in Phase 4 (`:fsm-allow-code`, default off) allows full-Clojure guards and actions evaluated in a restricted, serialized, 1-second-bounded sandbox over pure-data context — fail-closed, so a code-guard denies and a code-action no-ops until enabled. Design in [`docs/design/state-machine-design.md`](docs/design/state-machine-design.md).
- **Three conversational front-door agents over the event subsystem.** `schedule-agent` (time-triggered prompt jobs, `schedule$*`), `event-agent` (the flat event vocabulary — `event$*` / `reaction$*` / `watch$*`), and `state-machine-agent` (user-defined FSMs and their per-session runtime). Each is a thin CoAct-derived specialist adding **zero new commands** — they orchestrate command families that already ship, the same minimal-diff pattern as `config-agent`. They read capability gates but hand gate *writes* to `config-agent` by name, and each must write a per-conversation dossier, enforced by a hard final-step checklist. Designs in [`docs/design/`](docs/design/).
- **`by run --serve` — a headless daemon mode.** A no-TTY `by run` previously opened its per-session ask socket, immediately read stdin EOF, and exited — so a headless session could never stay alive to serve `by ask --attach <id>`. `--serve` installs a SIGTERM/SIGINT handler, keeps the session and ask listener alive, and parks until signalled, then shuts down gracefully. Documented in [`docs/core/session-channel.md`](docs/core/session-channel.md).
- **`--serve`'s companion: `by run` is now daemon-safe.** `run!` assumed a terminal — with no TTY the size probe fell back to 24×80 and the fullscreen path emitted alt-screen, mouse, and scroll-region control sequences to a non-terminal stdout. A new `stdout-terminal?` probe gates the alt-screen init, the welcome banner, startup notices, the input prompt, and the teardown line. A daemon `by run` now emits **zero** stdout (was ~2.9 KB of control sequences); a real terminal is unaffected.
- **Session lifecycle over the ask socket: `:new-session`, `:close-session`, `:rename-session`.** An external driver can now host many sessions in **one** JVM rather than one OS process each — create a session with its own agent, lock, and ask socket without switching the active tab, close a single session without killing the host (refusing to close the host's last chat session), and push a rename into a live process so `by sessions label` no longer waits for a restart to show up in the tab.
- **`:acp-client-fs` and `-m` model selection for ACP agents.** Advertising the ACP client filesystem capability is what makes a backend route file reads and writes back through Brainyard (mediated writes, diff rendering) rather than doing direct disk I/O; it was hardwired on and is now a config knob, default true. Separately, `-m` now reaches the ACP backend: the requested model is resolved against the backend's advertised ids and the status bar and transcript header show the model actually being served, with a one-time notice when the request did not match.
- **`:claude-code-max-turns`** makes the Claude Code agentic-loop turn cap configurable, read through a native-image-safe soft resolve so the provider still works when the agent component is absent.
- **A permission spec** ([`docs/specs/permission.md`](docs/specs/permission.md), area code PERM, 24 contracts) covering permission modes and resolution, the read allow-list versus the write always-allowed set, the interactive prompt and its grant caches, path validation, the tool-level scaffold, and the MCP fail-closed gate.

### Changed

- **`tool-args` is a plain JSON object rather than a name/value pair-list.** The CoAct/ReAct tool-args schema was `[:vector [:map [:name] [:value]]]`, a shape that induced malformed LLM emissions and forced a JSON-string/object coercion net to clean up after them. It is now a plain object (`[:map-of :any :any]`, MCP-style) — far more natural for a model to emit correctly, and it matches the native Clojure map the code channel already uses. The canonical tool-call schemas are consolidated so CoAct and ReAct share one definition instead of a local copy. Dispatch is backward compatible: the normalizer already accepted a map and still accepts the old pair-list. The same object-or-string widening is applied across every field that carries a structured payload — `task$run :tool-args`, `mcp$tools :arguments`, `hook-agent :match`, `tool-agent :input-schema`, and `event$define :payload-schema` — via two shared aliases split by native shape, so an object arg is validated as an object and a vector arg as a vector, and junk is rejected at the argument gate rather than becoming a silent no-op downstream.
- **Every LLM-facing event identifier is `:event-id`, typed as a keyword.** One concept had four names and two types across `event$define` / `event$remove` / `event$emit` / `fsm$send` / `watch$add` / `reaction$add`. Keyword typing serves both invocation channels with no coercion shim — the tool-calls channel sends a string and the arg decoder handles it, the code channel passes a native keyword. **Persisted and cross-process formats are deliberately unchanged**, so there is no migration and no version-skew risk: event definitions still store `:name`, watch specs still store `:emit`, and the `ask.sock` protocol plus `by events emit --event` still use `:event`. The seams are bridged, and reaction rules already on disk keep firing.
- **Self-improvement and memory consolidation run as bounded background tasks, not bare futures.** Skill distillation, skill refinement, and the memory consolidation cadence each spent tens of seconds in a sub-LM call off the turn thread — correct in principle, but a bare future per job was unbounded (one scorer per eligible turn, no damper), invisible (no queue, no record), and killed at JVM exit *after* the tokens were spent. They now submit to the task manager as a `:fn` job type: bounded by the fixed pool, **single-flight** per job kind and key, visible through `/task` and `task$detail` with a per-task `output.log`, and given a bounded grace period on `/quit` before shutdown cancels them. A consequence worth stating: a cadence boundary reached while a reduce is still running is now **dropped** — nothing is lost, the next boundary reduces whatever accumulated.
- **Skill distillation batches on a cadence instead of scoring every turn.** One sub-LM call per qualifying turn also meant a view that could only ever see one turn at a time — but a reusable procedure often spans turns (investigate, change, verify), and judged one turn at a time each looks like a fragment. `:at-cadence` (the new default) accumulates qualifying turns and judges the whole window in one call, plus a flush when the session closes so a session shorter than the window still distills something; `:per-turn` keeps the old shape. Only turn *numbers* accumulate — the window is re-read from the trajectory at batch time, so the accumulator stays small however long a session runs.
- **Dynamic skills load into the calling agent rather than a sub-agent.** Calling `skill$<name>` dispatched the question to a fresh skill-agent and returned that sub-agent's prose answer — so the agent that wanted the procedure never saw it, receiving a second-hand result produced by a different agent with a different toolset. A skill now loads into the **calling** agent, delivered two ways because neither alone suffices: returned as the tool result (usable on the current turn) and registered as a full-body live artifact reloaded fresh from disk (so later turns keep it). `dispatch: agent` in SKILL.md frontmatter keeps the previous sub-agent behaviour for procedures better run in an isolated context.
- **Skill discovery is local-first, ranked, and collision-safe.** `skills$find` shelled out to `npx` on any local miss — two subprocesses, measured at ~5 s, returning unrelated marketplace install candidates shaped like real matches. It is now installed-only, ranked, and offline (8–25 ms; a miss returns an empty vector), with marketplace lookup moved to a separate `skills$search`. Dynamic skill ids also collided across backends: registration followed list order, so the last write won and CLI-installed skills shadowed local ones — on a machine with two backends installed, 47 discovered skills collapsed to 35 ids with 11 silently overwritten. The most local backend now takes the bare `skill$<name>` id and the rest register as `skill$<backend>$<name>`, so all 47 stay reachable.
- **Skill refinement triggers on failed turns, not failed calls.** The old trigger — a `skill$<name>` invocation returning an error — only exists for *delegated* skills. Since skills now load into the calling agent by default, the call hands over the SKILL.md and succeeds, so a wrong procedure can no longer fail at the tool boundary at all and the trigger had gone quiet for almost every skill. A wrong procedure still shows up one level higher, as a turn that never reached its goal, so refinement now also judges each skill a *failed turn* loaded. Both triggers feed the same judge and the same single-flight key.
- **A per-channel output contract: `tool-channel?`, the mirror of `code-channel?`.** A CoAct agent can now be code-only. This sheds no capability — every tool stays callable as a sandbox function — so it drops a redundant JSON emission path, not tool access, and an invariant keeps at least one action channel alive. The DSPy signature and its instructions are specialized per channel: a disabled channel loses its output field, so providers with native structured output refuse the dead channel at the API level, and `react-agent` no longer reads 3.3 K of prose describing a code channel it does not have. Both-channels output is byte-identical to the previous static text, and all three call sites resolve the signature from the same place that shaped the prompt, so schema and prose cannot disagree.
- **Chain-of-thought reasoning is length-bounded, and the replayed iteration thought is capped.** The reasoning field carried no budget — just "step-by-step reasoning", which actively invites enumeration — and unbounded reasoning is paid for twice in the agent loop: once as output tokens, then again on every later iteration when it is replayed in the prompt. The description is now one shared prescriptive definition, and `:max-thought-chars` clips the replayed copy where the iteration record is built, so the TUI still shows full reasoning.
- **An unnamed `by ask` no longer writes memory.** A throwaway one-shot question is a throwaway: capture off cascades to graph extraction and consolidation. Recall deliberately survives, so `memory/recall` no longer requires `memory/capture`; naming a session opts back into full behaviour.
- **`:enable-fsm`, `:enable-scheduler`, and `:enable-reactions` default to true.** All three no-op with no rules, schedules, or machines defined, so the change only activates behaviour once you define something. `:fsm-allow-code` stays false — SCI code evaluation remains opt-in.
- **Six previously-proposed gates are now real, enforced config keys**, each wired to a genuine read site: `:enable-memory-recall` (which gates injection, not capture — off keeps recording episodes and stops putting them in the prompt), `:enable-compaction` (the automatic compactor only; an explicit `/compact` always runs), `:enable-live-artifacts`, `:enable-artifact-gc`, `:enable-acp`, and `:enable-gateway`. **All six default true** — each names behaviour that runs unconditionally today, so each is a kill-switch rather than a new opt-in, and a false default would silently disable working features on upgrade.
- **Restart-ness is derived rather than flagged.** The 13 per-key `:requires-restart` flags are gone, replaced by a derivation from each feature's lifecycle minus its live keys. Restart-ness was never a property of a key — it is a property of *when* its feature is read — so a key added to a startup feature now inherits the warning instead of relying on someone remembering a flag.
- **Dead config keys are now visible.** Loading global config silently dropped anything retired or misspelled, which is exactly how a key goes on sitting in `config.edn` looking effective. Unknown keys are now logged with their names and the file path.
- **Renamed:** `:enable-analytics-family` → `:enable-analytics` and `:enable-cross-turn-compaction` → `:enable-compaction` (with matching `BY_ENABLE_*` env vars), both now that the name collisions they were dodging have been cleaned up. Three internal `clj-sandbox` `:enable-*` locals that were never config keys are renamed to predicate form, so they stop costing a false hit on every search for a real gate.
- **Removed:** the four inert `:react-*` keys (`:react-loop-mode`, `:react-keep-thoughts-n`, `:react-keep-observations-n`, `:react-keep-iterations-n`), which had no readers — the machinery they would have tuned does not exist — and `:enable-budget-monitoring`, whose only plausible destination is unreachable from this workspace. Three docs that described them as live are corrected. Two dead TUI event renderers are also gone.
- **Writes to project source are gated on permission mode; the system temp directory is allowed by default.** The write gate's always-allowed set stays minimal agent scratch (`/tmp`, the system temp dir, `<project>/.brainyard/`); project source outside `.brainyard/` falls through to the permission function, so `:auto-approve` allows silently, `:ask-each-time` prompts, and `:deny-by-default` denies. Under `:ask-each-time`, a request whose paths all fall within the effective allowed-dirs is auto-allowed without a prompt, mirroring the read gate.

### Fixed

- **Task ids could collide across two `by` sessions open on the same project.** Ids came from a counter seeded once at startup from the largest `task-N` directory on disk. Task directories are project-scoped, not session-scoped, so two processes both seeded from the same scan and then both issued `task-n+1`, `task-n+2`, … — duplicate ids pointing at **one** directory, so the sessions interleaved lines into each other's `output.log` and clobbered each other's `meta.edn`. A GC sweep that reclaimed the newest directories could also lower the seed and hand a fresh session ids still live elsewhere. Ids are now `task-<base36 epoch-ms><random>`: time-ordered (lexicographic sort is creation order), unique within a process by a strictly-increasing clock ratchet, and separated across processes by the random tail. Legacy `task-N` directories still scan and sweep normally.
- **`skills$import` wrote the skill to the wrong place.** Arguments were passed positionally against a signature expecting a keyword argument, so the scope landed in the name slot and the name in the content slot — producing a directory named after the *scope* whose SKILL.md was the literal skill name, with the real body dropped into ignored kwargs.
- **A sub-agent wiped the root turn's loaded-skill set.** The session-end handler dropped the set on any instance close without checking whether the closing agent was the root. Sub-agents share the root session id and are auto-closed as soon as their call returns, so the *first* sub-agent a turn dispatched cleared the set before the turn ended — meaning any turn that loaded a skill and then delegated anything, the common case, silently lost the refinement signal. Found in live verification against a real TUI; all 180 unit tests had passed because they call the handler directly and never exercise a real sub-agent lifecycle.
- **Positional arguments were applied in hash order past eight parameters.** The `:defn` binding path derived argument order from the properties map, which stays insertion-ordered through 8 pairs and tips into a hash map at 9 — so a function with nine or more parameters had every value silently land in the wrong parameter. No error, just wrong data. Order now comes from the function's own arglists.
- **Two permission gates saw `nil` for every bound tool.** Tool arguments were re-stringified on the path every LLM tool call arrives through, so the `:agent.tool-use/pre` payload depended on how a tool happened to resolve. The MCP permission gate never matched a proxy call — the branch documented as fail-closed was skipped entirely — and the bash guard failed open, leaving the eval-agent read-only contract unenforced.
- **Reaction `{{key}}` interpolation dropped payload values.** Interpolation resolved only keyword keys and only substituted top-level strings, so events with no payload schema (which keep the string keys the emit boundary produces) rendered blank slots, and a nested `:emit` payload propagated the literal template downstream. Separately, `event$emit` now keyword-coerces its payload against the declared schema, so an idiomatic keyword-keyed schema validates *and* interpolation resolves — previously the only workaround was a string-keyed schema, which then broke interpolation the other way.
- **A throw in the ask worker wedged the queue permanently.** The worker caught only interrupts and cleared its handle only on normal completion, so an unprotected per-item side effect could kill the future while the handle still pointed at it — the respawn guard never fired and asks enqueued forever without draining. The per-item catch is widened, the handle is always cleared, and a done-but-not-nil worker is respawned.
- **`claude-code` rejected every request after the tool-args schema change.** The new bare map-of put the first one into the output schema, and the additional-properties pass injected `"properties": null` on an object that legitimately has no properties — invalid JSON Schema, which `claude-code` is the one provider to validate, failing the request before any LLM turn. Bedrock and free-llm were unaffected because they receive the schema as prompt guidance rather than as a validated parameter.
- **Mistyped and flattened LLM outputs are coerced rather than aborting the turn.** Structured-output handling gains a coerce-before-validate pass that repairs present-but-wrong-typed fields (a scalar for a vector field, `"false"` for a boolean), keeping a coercion only when it then validates; the coercion layer now also works on registry-ref schemas, where it had been entirely inert on the CoAct signature. A flattened single tool call is lifted back into its vector field, and a JSON-string container is reparsed. Placeholder emissions (a fabricated `noop` tool used to satisfy an always-act contract) are refused at lift time and routed to a single no-action nudge instead of up to five backoff retries.
- **Aborted turns were captured as memory episodes.** An unrecoverable LLM error stamps its reason *into* the answer, so by inspection it is indistinguishable from real content — which is how entries like `Q: hi  A: Agent stopped: request rejected (HTTP 401)` ended up in the recall corpus (a real database held 50 such episodes across 44 sessions). Deliberately narrow: only transport-level aborts are skipped, since exhaustion and loop-guard terminations stamp a best-effort progress summary that is worth remembering.
- **Re-asserting a graph relation inserted a duplicate edge instead of updating one.** The unique key included the validity timestamp, which defaults to now, and re-extraction is routine by design — a per-session run and a later per-user sweep overlap deliberately rather than risk skipping episodes. A partial unique index over live rows only preserves bi-temporal history while collapsing re-assertion. Verified against a copy of a real database: 137 edges to 126, no duplicate groups remaining, row ids and invalidated history preserved.
- **The batch-extraction watermark is persisted**, so a detached child and the live session no longer track independent positions over the same episodes — which had them each re-extracting the other's work, paying for the extraction twice and re-inflating the graph against its eviction caps.
- **`by ask` blocked for five minutes at session end.** The consolidation offload was wired only into the interactive path and the answer was emitted after close, so a one-shot ask waited out the full graph flush printing nothing: 295 s down to under 3 s.
- **The memory consolidation cadence inherited a 300-second job ceiling** sized for a sub-LM drafting a SKILL.md. A graph-path reduce over an 88-episode window measured 261 s — 87 % of the budget — on a two-turn session, so a longer session would be cancelled mid-reduce, plausibly after the extraction marker advanced but before the communities were summarized. The cadence job now carries its own mode-aware ceiling, and graph-mode consolidation is offloaded to a detached child so the work outlives the session rather than being killed at `/quit` after the tokens were spent.
- **The skill-distill pre-filter counted iterations rather than action steps**, so a turn batching a whole multi-step procedure into one code block scored 1 and was dropped without an LLM call — exactly the shape most worth distilling.
- **Tool arguments reached the model's own conversation history as `tool(=nil, =nil)`.** The compaction renderer walked the arguments map as the legacy pair-list; mapped over a map that destructuring sees map entries, whose keyword lookups are nil. Four rendering sites each printed their own shape; all now share one normalizer and read alike.
- **A newly created user tool or agent could not be called in the same turn.** Registration wrote the tool definition but not the live code-eval sandbox, whose bindings are snapshotted at turn start, so a create-then-call failed to resolve until the next turn rebuilt them.
- **`update-file` and `edit$apply` accept `old_string`/`new_string` aliases.** Models trained on other edit tools reflexively emit them; the aliases fold onto the canonical `:pattern`/`:replacement` at both the tool-call and direct-call layers, with an explicit canonical value always winning.
- **An HTTP provider with an unresolved base URL** now fails fast with an error naming the missing environment variable, instead of an opaque `URI with undefined scheme` at zero tokens and zero calls.
- **The Linear MCP seed pointed at a retired SSE endpoint** and could never connect as shipped; it now uses streamable HTTP with native loopback OAuth.
- **ACP plan entries rendered as blank todo rows** and never ticked completed items, because the backend emits a different shape than the TUI renderers read.
- **`/session new` left the status bar showing the previous session's agent** until the next redraw.
- **`todo-agent` routed multi-file changes to `edit-agent`**, which refuses them by contract, so the item stalled. Routing guidance now reserves `edit-agent` for a single tracked source file, with a post-flight rubric flagging items that violate it.
- Plus: `task$detail :last-n` typed as an int with coercion, non-string tool arguments stringified for string-typed parameters, and a stale test fixture repaired.

### Notes

- **JVM cold-start work was reverted after measurement proved the wins were an artifact.** Two lazy-require splits measured a 7.18 s → 5.02 s improvement, but `require main` / `--help` never creates an agent, so the agent roster — and transitively the memory subsystem — never loaded on the path being measured. A *working* TUI must load them, and with the roster loaded the wins evaporate; the splits also broke the JVM `bb tui` path outright, which headless measurement missed. Both are backed out. The one real lever is kept as opt-in AOT (`BY_AOT=1`, ~2.3 s). The honest conclusion is recorded in the design notes: the JVM cold-start floor is ~7 s from source, and instant start is the native `by` binary at 0.015 s.

## [v0.4.0] — 2026-07-12

### Added

- **User-defined events, reactions, and a watch loop — a pub/sub layer over the agent hooks bus and `ask.sock`.** External processes, the agent, and Brainyard itself can now define, emit, subscribe to, and react to named events. Declare an event (`event$define`, with an optional payload schema) and fire it from the agent (`event$emit`), from an external process over the session socket (`ask.sock` `:op :emit`, or the new **`by events emit`** CLI — the external twin of `by ask --attach`), or on a schedule; a subscriber streams matching events out over `ask.sock` `:op :subscribe`. A **reactor** turns a fired event into an effect via persisted `event → action` rules (`reaction$*`, under `.brainyard/reactions/`): a matching event can inject a turn, refresh a live artifact, write project memory, append to a passive `## Events` context section (seen next turn, no interrupt), or emit another event — with `{{payload}}` interpolation, a payload match filter, and a per-session fire budget bounding cascades. A **watch loop** (`watch$*`) extends the scheduler ticker to probe an external condition (shell command or file mtime) each tick and fire an event on a predicate (`:changed` / `:increased` / `:matches` / `:threshold` / exit-code) — the autonomous event source. The whole layer is built **over** the existing hooks bus (not a replacement) and is off by default (`:enable-reactions`, `:enable-scheduler`). Design in [`docs/design/event-bus-and-reactor.md`](docs/design/event-bus-and-reactor.md).
- **Prompt-cache arrangement — a multi-zone cache layout with cross-turn breakpoints and an opt-in 1-hour TTL.** The prompt is now partitioned into ordered cache zones by ascending volatility so a provider's prompt cache is reused turn over turn instead of being re-billed. The system prompt splits into three stable zones — `:agent-core` (static rules + substrates), `:session-context` (system info, tools, instructions, `BRAINYARD.md`, project memory), and `:user-context` — so a `BRAINYARD.md` edit or a tools-tier compaction invalidates only the session zone, not the static core. The append-only previous-turns chain moves into its own `:history-context` zone and demotes in batches (`:demote-batch`, default 10) so its cached bytes stay stable between demotions, and within a turn a user-message stable-prefix breakpoint (`:user-cache-boundary :iterations`) ends the every-iteration dead write at end-of-message — iterations 2..N now read the question, context briefing, and recalled memory from cache. An **opt-in 1-hour TTL** (`BY_CACHE_TTL=1h`, default `5m`) keeps the cross-turn prefix alive across human-paced gaps: on Anthropic-format providers via the `extended-cache-ttl` beta header, on **Bedrock Converse** via the `CachePointBlock` `1h` TTL (Anthropic Claude models; Nova stays 5m), and on **OpenAI/Azure** via `prompt_cache_retention "24h"` plus a session-stable `prompt_cache_key` (both gated to `#{:openai :azure}` so OpenAI-compatible third parties never receive unknown fields). Observability: each call emits `::cache-zones` (zone key + size + fingerprint) and cache read/write tokens, silent zone-location fallbacks now warn, `/usage` gains a "Cache net saved" estimate, and `/usage --breakdown` attributes tokens per user-message field. Live-validated on `bedrock/nova-lite` and `gpt-4.1-mini` (cross-turn calls read 12–13K cached tokens at −63% to −75% cost). Design in [`docs/design/prompt-cache-arrangement.md`](docs/design/prompt-cache-arrangement.md); knob documented in `.env.example`.
- **Conversation timeline — completed Q/A collapses to `[Turn N]` references so it isn't billed twice.** Every finished turn's Q/A previously rendered both in the cached previous-turns zone and again verbatim in the volatile conversation window (~1.2–2.5K tokens re-billed every turn). The window is now a session timeline: your own completed Q/A pairs older than the `:conversation-keep-verbatim` most recent (default 2) collapse to `[Turn N]` → Previous Turns references (adjacent refs merge into ranges), while sub-agent messages, system/wakeup notes, and the recency tail stay inline. `trajectory$search` is the drill-down for a `[Turn N]` reference whose detail progressive compression already dropped. Set `:conversation-style "full"` to restore the legacy verbatim window.
- **Always-alive subagents with an `agent-registry$*` lifecycle surface.** A dispatched subagent is now kept alive after it answers, so a parent can follow up on a later turn instead of re-dispatching a fresh instance. The dispatch returns an askable `:subagent-id`, and a new lifecycle tool family lets an agent manage the roster: `agent-registry$list` / `agent-registry$detail` / `agent-registry$ask` (with reach, busy, and depth guards; reuses the previous-turns chain) / `agent-registry$close`. `agent-registry$ask` sends a follow-up question to a live instance, its reach fenced for safety: a **root** agent may ask a **sibling root** or a subagent in its **own session** (not another root's subagents); a **subagent** may ask **only** instances it dispatched (never its root, siblings, or other roots — an upward ask could loop). The registry is bounded by an LRU cap (`:max-subagents-per-session`) that evicts the least-recently-used idle instance on each dispatch; cancelling a subagent's background task closes its instance. When such a call detaches into a background task, the "STILL RUNNING" marker now carries a lifecycle note (ask the instance-id, not the task-id). Gated on `:enable-subagent-calls`; `/agent status` shows a Lifecycle line. Design in [`docs/design/agent-lifecycle-management.md`](docs/design/agent-lifecycle-management.md).
- **`by run -s`/`--session <id>` pins a new session id.** `run` previously had no way to choose the session id (only `BY_SESSION_ID`, which silently reused or clobbered an existing session dir). `-s`/`--session <id>` starts a **new** session with that exact id for deterministic `sessions/<id>/` paths (scripting, `ask --attach` targeting); if the id already exists it errors ("use `--resume <id>` to reattach") and exits 1 rather than clobber. Forwarded through the `--web`/`--sandbox` re-exec child.
- **`time$*` tool family — `time$now`, `time$add`, `time$diff`.** A `time` tool family backed by a pure `core.timeutil` namespace returns wall-clock as a canonical instant map (`time$now`), does calendar-correct date math (`time$add`, DST/month/leap aware), and reports signed totals plus a humanized magnitude and calendar breakdown between two instants (`time$diff`). All three share one instant shape so field names never drift. The bespoke `(now)` sandbox binding is retired in favor of `time$now`, and the prompt's "- Now:" snapshot now uses the same canonical formatter.
- **Tool calls render collapsible `Call` and `Result` boxes in the iteration block.** Tool-channel calls now mirror the code channel: short calls stay compact one-liners, but code-like args (multi-line or over 120 chars) drop into a boxed, file-backed collapsible `Call` section, and the full tool result — normal output or a returned `{:error …}` map alike — renders in a collapsible `Result` box (a red `Error` box when the call failed) instead of only a truncated char-count. Arg names and values are styled through two new themeable tokens (`:tool/arg-name`, `:tool/arg-value`). A **non-error map result** (e.g. `bash`'s `{:status … :exit-code … :output …}`) now renders as `name: value` key-value lines inside the `Result` box — the same readable treatment as the `Call` args box — instead of a single cramped `pr-str` blob; error maps stay a compact `pr-str` so the red `Error` box reddens them uniformly.
- **Background memory activity is now visible in the TUI.** L2→L3 consolidation and context-graph extraction previously happened silently (off the agent thread, in async/fire-and-forget work), so a user never knew memory was working — or, on the multi-second graph path, why anything paused. A dedicated always-on display now surfaces these milestones in the scrollback as muted `🧠 memory · …` lines: `consolidated 12 episodes → +3 facts (L3)` (heuristic) / `consolidated 4 communities → +4 summaries (L3)` (graph reducer), `graph +5 entities, +7 links` (extraction), and a warning-tinted `consolidation failed`. No-op consolidations and zero-yield extractions are suppressed, so only real milestones show; per-turn capture, recall, and retention sweeps are intentionally omitted (milestones only), and session-end folding stays on its existing `/quit` line. On by default and toggleable live via `:show-memory-activity` (env `BY_SHOW_MEMORY_ACTIVITY`); the signal source is the memory pipeline's existing mulog events routed through a second TUI publisher, so the verbose `[mulog]` firehose no longer double-prints them.
- **Sub-agent activity survives into the permanent record and is visible in quiet mode.** The consolidated subagents block already showed live per-sub-agent state (started / running / tools / code / done), but two holes are now closed. (1) **The frozen record kept only a summary line** — the tool/code activity was rendered only while a sub-agent was `:running`, so once it finished the permanent scrollback showed *that* it ran, not *what* it did. The activity totals (`· 5 tools · 2 code-blocks`) now ride the summary line itself, so they survive the `:running → :done` collapse (the redundant running-only `(+N tools used)` footer is dropped). (2) **`:quiet` display-format suppressed the animated block entirely**, hiding all sub-agent milestones. Quiet mode now emits compact discrete lines pinned to the root's session — `● [research-agent] started` and `✓ [research-agent] done · 5 tools, 2 code-blocks · 12s` (`✗ … error` on failure, `↳`-indented for nested sub-agents) — matching quiet's existing think-bullet aesthetic. The close line fires once, guarded on the real done-transition so the dual `ask/post` + `instance/closed` funnels don't double-emit.
- **`list-tools` with no arguments returns a grouped, compact index.** A bare `list-tools` dumped the full collapsed metadata (including input/output schemas) for every visible tool (~200) — far too much context. It now returns a grouped-by-family index (`{:total N :families {family [{:id :description} …]}}`), one line per tool with schemas omitted, so the roster stays scannable and the model drills into a specific tool via `get-tool-info`. Filtered calls (`:pattern` / `:type`) and `:grouped false` still return the flat detailed list.
- **MCP tool calls are gated by a fail-closed permission check — the same approval UI as `write-file`/`bash`.** Configured MCP servers expose external, side-effecting tools (create a Linear issue, post to Slack, send mail), and any agent in the fleet can now invoke them inline via the MCP substrate — so a side-effecting MCP call now **requires approval before it runs** instead of executing silently. A single `:agent.tool-use/pre` gate covers **both** ways a tool is called — the registered `mcp$<server>$<tool>` binding *and* the `mcp$tools :op :call` proxy (including multi-call batches) — and routes through the **same permission prompt that already gates `write-file`/`bash`** (in-stream or tmux popup, with a per-session "always (remember server)" / "never" cache). It honors the existing `[:permissions :mode]` policy: `:auto-approve` allows everything, `:deny-by-default` blocks every side-effecting MCP call, and `:ask-each-time` (the default) prompts interactively — and **fails closed when there's no interactive channel** (a headless `ask`, a sub-agent), refusing the call rather than running it unprompted, mirroring how `write-file` already behaves. Read-only calls don't prompt: a tool whose MCP `annotations.readOnlyHint` is set is auto-allowed (read from the server's own `tools/list`, including for proxy-only tools never registered as bindings), as is any tool matching a glob in the new **`:mcp-allow-tools`** config key (`server/tool` patterns, `*` = any run — e.g. `"linear/*"`, `"slack/post_message"`). The classification is **not** a model-side read/write guess — it's the server's declared annotation plus your allowlist, with everything else fail-closed. A refused call returns a clear, actionable error (approve interactively, add an allowlist glob, or set `:auto-approve`) and the turn continues. **Behavior change:** MCP calls that previously ran ungated — including `exec`'s `:via :mcp` route, `mcp-agent`, and headless `ask` — now prompt (or refuse, headless) for side-effecting tools unless `readOnlyHint`-marked or allowlisted.
- **Context-graph memory — a typed entity/relationship graph + semantic vector index over long-term memory, with a self-contained in-binary embedder.** Opt-in via `BY_ENABLE_GRAPH_MEMORY` (default off, fully non-regressing — an empty graph leaves recall byte-identical to the existing FTS/BM25/RRF behavior), Brainyard's long-term store (`components/memory`) gains a **context graph** that adds two recall signals fused into the same Reciprocal Rank Fusion: **semantic similarity** — a `sqlite-vec` vector index over L3 facts that catches matches sharing no keywords (e.g. "seatbelt sandbox" ≈ "OS write-containment policy") — and **relational, multi-hop** recall — typed, bi-temporally-versioned edges between entities (config keys, components, files, people, concepts) traversed 1–2 hops and surfaced in a new **"## Related"** briefing section (e.g. `BY_SANDBOX_INTEROP —configures→ clj-sandbox —part_of→ code-eval`). The graph **populates itself**: an async LLM extraction sidecar hung off the capture pipeline distills entities + relationships from episodes (`BY_GRAPH_EXTRACT_MODEL`, any chat model, e.g. `bedrock/amazon.nova-lite-v1:0`), and graph-community detection + summaries supersede the old heuristic L2→L3 time-bucket reducer — clustering by relatedness rather than by time window. Embeddings can be **fully self-contained**: the default `BY_GRAPH_EMBED_MODEL=static` is a pure-JVM **Model2Vec** static embedder (`potion-base-8M`, 256-dim) bundled into the binary — no embedding server, no native libraries, no native-image risk — so semantic recall works out of the box and your memory data never leaves the machine; power users can instead point it at any OpenAI-compatible `/embeddings` endpoint (`ollama/nomic-embed-text` (local), `openai/text-embedding-3-small`). Because vectors from different embedders aren't comparable, **changing the embedding model is detected by fingerprint and *pauses* semantic recall** — falling back to keyword search rather than ever serving a silently-wrong ranking — with a one-line startup banner and a `memory$status :vec-index` flag, until you rebuild the index with the new **`memory$reembed`** command. The bundled `sqlite-vec` extension and Model2Vec model are sha-pinned and fetched into the native image by `bb sqlite-vec:fetch` / `bb model2vec:fetch`. Design in [`docs/design/context-graph-memory-design.md`](docs/design/context-graph-memory-design.md); steered by the `BY_ENABLE_GRAPH_MEMORY` / `BY_GRAPH_EMBED_MODEL` / `BY_GRAPH_EXTRACT_MODEL` / `BY_GRAPH_EMBED_DIMS` env vars (annotated in `.env.example`).
- **`trajectory$search` — on-demand recall of past tool calls and code evals.** With routine tool/eval results no longer in semantic memory (see the capture change below), agents can now pull their *operational* history back when they need it: `trajectory$search` queries the session trajectory — every past tool call (`name`/`args`/`result`) and code evaluation (`code`/`result`/`output`/`error`), recorded per turn — filtered by `:query` (substring across all of those), `:tool`, `:kind` (`tool`|`code`), `:turn-id`, and `:limit` (most-recent first). This is the clean split: `memory$recall` returns durable *knowledge* (conversation + facts), `trajectory$search` returns *what you did and what it output* (e.g. a prior `bash`/file result or an eval value) — so operational detail stays fully available without flooding recall. Read-only and session-scoped.
- **Colon-command introspections are recorded into the model's context as Live Artifacts.** When you run a colon command at the TUI prompt (`:list-tools`, `:get-tool-info`, `:task$list`, `:time$now`, …) to inspect tools or state, the interaction — the command line plus a one-line digest of its result (`→` on success, `✗` on error) — is now captured as an inline Live Artifact tagged `:origin :console` and badged "🔎 you inspected". Because it rides the existing Live-Artifacts plumbing, it survives the turn reset and surfaces in the `## Live Artifacts` section on subsequent turns, so the agent becomes aware of what you've been poking at (a signal of intent) without you having to restate it. The entries are ordinary artifacts: they show up in `artifact$list` with `origin "console"`, are LLM-removable via `artifact$remove`, and are evicted oldest-first by the `:drop-live-artifacts` budget reducer (they're unpinned). A rolling window keeps only the newest few and dedupes a consecutive identical invocation. Three flat config keys steer it: `:enable-console-activity` (default `true`), `:console-activity-max-entries` (default `10`), and `:console-activity-result-chars` (default `200`, the per-entry result-digest cap).
- **`by memory` — deterministic, non-LLM maintenance on the long-term store, plus `ask --session` to thread memory across one-shot questions.** A new top-level subcommand operates directly on `~/.brainyard/memory/<user-id>.db` outside any agent session: `by memory consolidate -u <user> [-s <session>] [--reducer heuristic|community]` promotes L2 episodes into L3 semantic facts (the deterministic trigger the agent-driven essence path can't be — it's async/LLM-mediated); `by memory graph-build -u <user> [-s <session>]` **synchronously** extracts entities/relationships from L2 into the context graph (the async capture-time extractor is dropped by the 1s shutdown drain on a one-shot `ask`, so a blocking build is required for scripting/backfill — needs the graph tier configured); `by memory stats -u <user>` reports L1/L2/L3 counts; and `by memory graph -u <user> --json` dumps the entire context graph — every node + valid edge + counts — as JSON for visualisation/export (an unscoped full-graph read; empty when the graph tier was never populated). Separately, `by ask` gains **`--session`/`-s`** to pin the session id (default: a fresh ephemeral `ask-<millis>`) — reuse the same id across one-shot asks so session-scoped L1/L2 recall links them. Together these make the memory pipeline scriptable end to end.
- **Memory test harnesses (`bb test:memory`, `bb test:memory:l3`, `bb test:memory:l3-graph`).** Three real-LLM, self-cleaning harnesses under `scripts/` exercise the full capture → persist → recall loop against a throwaway user/db: session-scoped L1/L2 recall across separate processes; cross-session L3 recall via the heuristic reducer; and cross-session L3 recall via the graph-community tier (extract → community summaries → recall).
- **Per-agent black-box test harnesses (`scripts/test-agent-*.sh`, `scripts/test-agent-matrix.sh`).** One headless harness per agent — `coact`, `react`, `edit`, `plan`, `todo`, `exec`, `explore`, `eval`, `main` — drives the shipping binary via `by ask --json` and asserts on the durable side effects each agent is contracted to produce (applied edits + `Saved edit:`/`Rollback:` lines; auto-persisted plan/todo/eval dossiers and their `next_agent:` handoffs; explore findings; the `main-agent` routing log), pairing a deterministic side-effect probe with a softer LLM-output assertion so a failure localizes to the machinery or the surfacing. Each runs in full isolation (throwaway `-u` memory DB + a throwaway git-repo project pinned via `BY_PROJECT_DIR`, so nothing touches the real repo), honors the `0`/`1`/`2` exit contract (provider-quota exhaustion is classified as `2` cannot-run rather than a failed assertion), and is matrix-able across providers via `test-agent-matrix.sh`. Design and per-agent case tables in [`docs/test-harness.md`](docs/test-harness.md).

### Changed

- **A dispatched sub-agent no longer draws a redundant per-task block.** When a root agent dispatches a sub-agent (an `:type :agent` tool) that runs long enough to detach into a background task, the TUI used to show *two* live blocks for the same work — the consolidated subagents block AND a generic per-task block. The per-task block is now suppressed for sub-agent dispatches (detected via the `:coact/subagent-id` marker that `adopt-tool-into-task` already stamps on such tasks), since the subagents block covers them more richly. The task itself is unaffected — `task$list` / `task$detail` / `task$cancel`, the pending-task briefing surfaces, and the "moved to background" markers all still work; only the duplicate live block is dropped.
- **LM identifiers are unified on `provider/model` — the colon form stays a legacy fallback.** The canonical separator is now a slash (`bedrock/amazon.nova-lite-v1:0`, `openai/gpt-4.1-mini`); `parse-lm-str` prefers it and splits on the first `/`, so model ids that themselves contain a colon stay intact, and it falls back to the legacy `provider:model` when no slash is present. The TUI usage tables, session indicator, and memory's graph-model resolution now render the canonical `provider/model` label. Existing `provider:model` inputs keep working.
- **Graph-mode session-end memory consolidation is offloaded to a detached child, so `/quit` returns immediately.** With graph memory on, the final `L2 → graph → L3` consolidation (batch extraction + per-community LLM summaries) could block `/quit` for up to several minutes. That tail is now handed to a detached `by memory reduce -u <uid> -s <sid>` child (survives terminal teardown via `trap '' HUP INT TERM` + `setsid`/`perl`), so exit is instant and the reduce finishes afterward; the child re-execs the real binary (not a `BY_WEB_SELF` ttyd stand-in), overridable via `BY_MEMORY_SELF`. `/quit` now reports the child's PID ("Spawned background process (PID …) to fold this session into long-term memory — it continues after exit"); heuristic mode still folds inline and reports the elapsed time. A blank session id is guarded so consolidation can never accidentally run over the user's entire L2 history, and SQLite gets `busy_timeout=30000` so the child and the TUI don't lose a WAL write race. Related: the L2→L3 consolidation cadence tightens (`:memory-consolidate-every-n-turns` default 12 → 5) for finer-grained, less-lossy consolidation, and the app log now rotates at 50 MiB (3 backups) instead of growing unbounded.
- **`max-iterations` no longer keeps a redundant TUI-state mirror — `/status` reads the config value directly.** The BT loop already resolved the iteration cap live from `get-config :max-iterations` each turn; the parallel `!tui-state`/session copy (synced by hand at `/config`, `/continue`, and every `set-agent!`) was display-only and could drift. That mirror and all its sync points are removed — `/status` and the status summary now read `get-config`, so the displayed cap always matches what execution uses. The CLI `-n`/`--max-iterations` flag still seeds a per-agent override via the `create-tui-agent!` setup option (both `:max-iterations` and `:display-format` injections are now nil-guarded so an absent flag falls through to the session/global/default layers).
- **`:display-format` is now a first-class config key — the single source of truth for TUI display verbosity.** The `/display-format` command and the `-v` flag both resolve through `get-config :display-format` (default `:normal`) instead of a separate TUI-state atom, so the value follows the standard precedence chain (env `BY_DISPLAY_FORMAT` > per-agent > session > `.brainyard/config.edn` > default) and can also be set via `/config display-format quiet`. `/display-format <level>` writes the config key (per-agent override + persisted); `-v` seeds a transient per-agent override at startup. Rendering (`quiet?`, verbose BT-traces) reads the config value directly.
- **The TUI display-verbosity command is renamed `/verbose` → `/display-format`.** The command that shows/sets the terminal display detail level (`quiet` / `normal` / `verbose`) is now `/display-format` — a clearer name that won't be confused with the separate `:verbose` runtime output-mode colon-command. The level values are unchanged (`/display-format verbose` still enables full BT traces). **Behavior change:** `/verbose` is no longer recognized; use `/display-format`. Autocomplete, `/help`, and the idle-prompt tips all reflect the new name.
- **`:quiet` display-format is now a compact think-bullet view instead of answer-only.** Previously `:quiet` suppressed every intermediate widget and showed only the final boxed answer. It now surfaces a minimal, scannable trace: each **iteration** renders only its think text as a `● <think>` bullet (no header/tool/eval lines), each **sub-agent**'s think text renders as a name-prefixed `● [agent-name] <think>` bullet, and the **final answer** is printed as plain markdown **without the highlighted box** (indented to align with the goal-status / next-prompt lines). Think text is wrapped and capped at the same `think-max-lines` as the normal view; iterations with no reasoning stay silent. Each think bullet and the answer are separated by blank lines for readability. The sub-agent roster block, TODO block, and per-iteration observation lines remain suppressed in `:quiet`. `:normal` and `:verbose` are unchanged.
- **L2 memory truncation is relaxed, configurable, and surrogate-safe.** The captured-episode storage caps were far too tight (question 1000 / answer 3000 chars), silently dropping the tail of any long answer from what FTS could ever match. They're now decoupled into two layers and relaxed: **storage** (what an episode persists, hence what's keyword-searchable) defaults to question 8000 / answer 16000, while the **recall snippet** (what each recalled hit actually shows in the prompt) is a separate, smaller cut raised from 240 → 600. Relaxing storage costs only DB/FTS bytes, not prompt tokens, since recall re-snips independently. All three are config keys — `:memory-question-max-chars` (8000), `:memory-answer-max-chars` (16000), `:memory-recall-snippet-chars` (600) — threaded into the capture parser at `start-capture!` and bound for recall rendering. Both truncation points are now **surrogate-safe**: a cut that would split a UTF-16 surrogate pair (e.g. an emoji at the boundary) backs off one char instead of leaving a dangling surrogate that mangles to a replacement char when encoded to UTF-8 for SQLite.
- **Heuristic L2→L3 consolidation now actually fires for ordinary conversation.** The heuristic reducer bucketed episodes by their tag set minus `event:`/`kind:` — but kept the auto-extracted per-message `topic:` tags, which are unique per turn (`topic:teal`, `topic:photon`, …). So every turn landed in its own bucket, the batch-size threshold was never met, and consolidation silently produced nothing for any varied real conversation. The bucket key now also excludes `topic:` tags, reducing to the stable structural tags (primarily `role:`) so a run of conversation in one time window batches into a single per-(role, window) digest. (Topic/entity-cohesive consolidation remains the graph-community tier's job; this is the lightweight digest tier.)
- **Memory capture is leaner and no longer recalls your own question.** The L2 capture pipeline previously wrote one episode per lifecycle event — the bare `:agent.ask/pre` question, the `:agent.ask/post` answer, and *every* tool call and code eval — so a single turn exploded into many fine-grained, often-duplicated episodes, and (worst) recall run over the current question matched the just-captured question as its own top hit. Capture is reworked around what's actually worth remembering: the conversation is now **one Q&A episode written at `:agent.ask/post`** (question + answer together), carrying a content-addressable `entry_id` so re-asking the same thing **upserts** instead of duplicating; the bare pre-question is no longer captured at all (it fired *before* the turn's recall, which is why it self-matched). Tool-use and code-eval are captured **only on error** — a successful tool/eval is operational noise for semantic recall and already lives in full in the trajectory log and the `memory_audit` trail — so failures stay recallable ("last time this errored with …") without the per-event flood. Net effect: far fewer, higher-signal L2 episodes, no cross-turn question self-recall, and no duplicate episodes for repeated questions or tool calls. (`:agent.ask/pre` is no longer a subscribed capture hook.)
- **Config precedence: environment variables now win.** `get-config` resolves through `ENV > per-agent override > session > .brainyard/config.edn (merged over static defaults) > schema default` — previously env vars were the *lowest*-precedence fallback (read inside each key's `:default-fn`), so a persisted `config.edn` value silently beat them. Env reads now live in a dedicated per-key `:env-fn` evaluated first; a set variable overrides every persisted/in-memory layer (a sentinel distinguishes a real `false`/`0` from "unset"). Affects the env-bound keys `:nrepl-enabled?` (`BY_NREPL_ENABLED`), `:nrepl-port` (`BY_NREPL_PORT`), `:ask-channel-enabled?` (`BY_ASK_CHANNEL`), `:ask-timeout-ms` (`BY_ASK_TIMEOUT_MS`), and `:sandbox-interop` (`BY_SANDBOX_INTEROP`). Each resolution is mulog-tracked once per (key, source) via `::config-resolved` so the winning layer is observable. **Behavior change:** e.g. `BY_NREPL_ENABLED=true` now enables the nREPL even when `config.edn` sets `:nrepl-enabled? false`.
- **The Tavily web-search API key is env-only — no longer a config key.** `:tavily-api-key` is removed from the config schema; the web-search tool reads `TAVILY_API_KEY` directly from the environment. A secret has one source of truth — its env var — so routing it through config bought nothing (no agent set it) and cost surface area: it could be planted in a committable `config.edn` and it needed a redaction special-case to keep it out of LLM-facing config displays. Dropping it from the schema structurally removes both risks. (This is the same decision already made for `--working-dir`.)
- **The on-demand usage-guide tool and sandbox binding are renamed `usage` → `usage$guide`.** Both the tool exposed on the tool-calls channel and the matching SCI sandbox binding now follow the `$`-suffixed tool-naming convention (like `task$detail`, `log$turns`, `artifact$add`) and no longer collide by name with the `/usage` meta-command (token/cost summary). The sandbox binding is no longer a hand-written special case — `usage$guide` is now bound through the generic auto-tool-binding path like any other tool: its `:topic` input is a keyword, so agents call `(usage$guide :topic :memory)` in a Clojure fence (`(usage$guide)` lists topics). A known topic returns the guide as a plain string so it renders verbatim (real newlines) in the iteration record rather than a pr-str'd map with escaped newlines; listing/unknown-topic calls return a small map. The registered tool id is `:usage$guide`. All system-prompt pointers, usage guides, and the just-in-time nudge were updated to the new name and call shape.

### Fixed

- **`trajectory$search` is now actually bound to the roster — it was taught but never invocable.** The operational-trace lookup was defined and every coact-derived agent was told to call it, but no roster vector carried the var, so `all-common-commands` never included it and no agent could invoke it. A new `trajectory-commands` vector rides the common roster, and a test pins the guidance-to-binding sync (the same failure class as the earlier dropped substrate sections — prose present, mechanism unwired).
- **Bare Amazon Nova ids auto-route through a cross-region inference profile.** Amazon Nova can't be invoked on-demand with a bare model id in most accounts/regions (Bedrock returns "…with on-demand throughput isn't supported. Retry with an inference profile"), so `/model amazon.nova-lite-v1:0` and direct `by ask` / `by memory reduce` calls all failed while the profile-prefixed Anthropic-on-Bedrock ids worked. `create-lm` now rewrites a bare `amazon.nova-*` id to the cross-region profile for the resolved AWS region (`us-*` → `us.`, `eu-*` → `eu.`, `ap-*` → `apac.`); already-prefixed, non-Nova, and Anthropic ids are untouched. Any other model that needs a profile gets an actionable hint appended to the AWS error.
- **Graph extraction applies its JSON schema on non-native providers, so Bedrock actually extracts.** `make-extract-fn` called `chat-completion` with `:json-schema`, but for providers without native structured output (`Bedrock`, `Anthropic`, `Ollama`) the prompt-injection fallback was dead code — the schema was silently dropped, the model got no output contract, and graph extraction produced **0 nodes** for `BY_GRAPH_EXTRACT_MODEL=bedrock/*` (exactly the model `CLAUDE.md` recommends). `chat-completion` now injects the schema into the system prompt when the provider lacks native support and it isn't already pre-injected by the DSPy path; native-schema providers are unchanged. Extraction also logs `::extracted {:entities :relations}` so a model ignoring the JSON contract shows `0/0` in the app log instead of looking like nothing was worth recording.
- **`claude-code` structured-output and streaming are hardened against prose replies and mid-stream failures.** Three related fixes: a `claude-code`-scoped system-prompt directive is appended whenever structured output is active (the CLI exposes `StructuredOutput` as an *optional* tool, so on large prompts the model could bypass it and answer in prose that fails JSON parsing); the streaming path now catches `Throwable` (an `Error` like a `StackOverflowError` from a resumed large-context subagent previously escaped with the `claude` subprocess still alive), guards the timeout, and throws a clean classifiable error on an unrecoverable nonzero exit instead of returning blank text; and a pure-prose reply with no JSON envelope is now kept **as** the iteration's thought (routing the schema correction to the model-visible notices) rather than being buried in a fake code-result error field.
- **The conversation-timeline transform no longer crashes on the first turn of a fresh session.** `completed-turn-units` seeded segment starts with `[0]` unconditionally, so an empty message window (a fresh session's first turn, after the question tail is dropped) hit an `IndexOutOfBoundsException` before the transform's own guard could short-circuit — aborting the turn before any LLM call with a silent return to idle. The empty window now returns `[]`.
- **Per-turn token usage is recorded in the trajectory, not the session-cumulative total.** `trajectory.edn` recorded `:usage`/`:cost` from the session tracker's running cumulative totals, so every turn's record showed the whole-session total climbing monotonically. A cumulative snapshot is captured at turn start and diffed at finalize, so each record now carries exactly what that turn added (resume-safe — the baseline carries the restored cumulative).
- **`claude-code` structured output is unwrapped when a model returns the `{"value":"…"}` envelope — fixes coact-derived agents aborting on `claude-code:sonnet` (and `opus`).** The `claude-code` provider drives structured output through a synthetic `StructuredOutput` tool (exposed via `--json-schema`), and the model returns the payload in that tool call's `input`. Some models — reproducibly `claude-code:sonnet`, and by the same path `opus` — wrap the entire payload in a single `{"value":"<stringified-json>"}` field instead of filling the schema fields directly (as `claude-code:haiku` does). Downstream parse+validate then saw a lone `value` key with the real signature fields absent, so any agent that leans on the tool/code channels (`coact-agent` and its derivatives — `edit`, `explore`, `plan`, …) aborted mid-turn with `"your previous output did not match the required schema {:tool-calls ["invalid type"], :goal-achieved ["should be a boolean"]}"` once the re-prompt recovery budget was exhausted — the model was answering correctly, but the wrapper made the answer unreadable. Both extraction paths now unwrap the envelope via a shared `value-wrapper?` guard: the non-streaming `extract-structured-output` (tool-input map) and the streaming `chat-completion-stream` result assembly (the accumulated `partial_json` / inline `StructuredOutput` candidate) — the latter being the path `by ask` and the TUI actually use, which is why an initial non-streaming-only fix wasn't enough. A real signature never has a lone `value` string field, so the unwrap is unambiguous and cannot regress `haiku` (multi-field input) or natural-language text (passed through untouched). Verified end to end: `claude-code:sonnet`/`opus` `coact`/`edit`/`explore`, which aborted before, now run to completion (0 schema aborts across the per-agent test matrix).

## [v0.3.3] — 2026-06-22

### Added

- **OAuth for MCP HTTP servers — device flow, native loopback, dynamic client registration, and 401-challenge discovery.** Brainyard can now authenticate to OAuth-protected MCP servers (e.g. Notion's hosted `https://mcp.notion.com/mcp`) end to end, with no hand-copied tokens. A new brick — **`components/clj-oauth`** — implements the OAuth 2.0 Device Authorization Grant (RFC 8628), Authorization-Code + PKCE (RFC 7636) over a **native loopback redirect** (RFC 8252, a throwaway `127.0.0.1` HTTP listener captures the `?code` callback so the browser round-trip completes without an out-of-band paste), **Dynamic Client Registration** (RFC 7591), and authorization-server discovery (OIDC `/.well-known/openid-configuration`, falling back to `/.well-known/oauth-authorization-server`, RFC 8414). When an HTTP MCP server answers `initialize` with `401`, the `WWW-Authenticate` challenge is parsed for its protected-resource-metadata pointer (RFC 9728) and the issuer is discovered automatically; the flow is then chosen per server (`:device` / `:loopback` / `:paste`, default `:auto` based on what the server advertises). Tokens persist in a hardened store under `~/.brainyard/oauth` (mode 0600, atomic writes, keyed by `(account, user)`) with provider-agnostic refresh, and an optional OS-keychain backend (`security` on macOS, `secret-tool` on Linux — both subprocess-based, no JNI, native-image safe). Authenticate a server with **`/mcp <server> auth`**; the verification box (device user-code + URL, or a browser link) renders inline, with a scannable QR code via `qrencode` when it's on `PATH`. Two new flat config keys steer it: `:oauth-flow` (`auto` | `device` | `loopback` | `paste`) and `:oauth-token-store` (`auto` | `file` | `keychain`), plus `:oauth-qr?`. A ready-to-try **`notion2`** seed ships in the MCP config (native `:http`, `:flow :auto`) so the whole chain — 401 → discover → register → browser → loopback callback → token exchange → connected — can be exercised against a real provider.
- **Long-running MCP operations run off the command thread behind a live spinner.** `/mcp <server> start | stop | auth | status` block on the network — the `initialize` handshake, token exchange, or the user authorizing in a browser — and previously froze the TUI until they settled. Each now runs on a background thread behind a one-line braille spinner (`⠋ Connecting <server>…`) so the input bar stays responsive; when the op settles the spinner is disposed and replaced by a single outcome line (`Started <server>` / `Auth failed for <server>: …`), and the hardware cursor is returned to the input prompt. `status` only detaches when the server is connected (the disconnected detail is a local read and stays synchronous). The spinner respects the autocomplete overlay — paints defer while a menu owns the screen and resume once it's dismissed.
- **Usage guides are delivered just-in-time and exposed as a tool.** The per-tool usage guidance that helps the model call tools correctly is now pushed exactly when it's needed — surfaced on a malformed first tool call (not only on later ones) — and is reachable on demand via a `usage` tool backed by an open registry, so an agent (or its sandbox binding) can pull the guide for a specific tool/topic instead of carrying every guide in the system prompt. A new `:scope` tier keeps only system-level guides riding the system prompt, and the CoAct large-results playbook is slimmed, deferring the detail to `(usage :truncation)`.

### Changed

- **`/login` and `/logout` are scoped to auth providers; MCP-server auth lives under `/mcp`.** The two command surfaces no longer overlap. `/login` now reports auth-provider status (e.g. Anthropic) and signs in to a provider; `/logout <provider>` signs out. (Anthropic subscription OAuth remains restricted to Claude Code / claude.ai and can't be completed here; other providers authenticate via API keys in your `.env`.)

### Fixed

- **`clj-http-native` honors `:content-type :form` and explicit string content types.** The client previously only special-cased `:content-type :json`; any other value — including `:form` and raw strings like `"application/x-www-form-urlencoded"` — was dropped, so the header never reached the server. OAuth token endpoints require form-encoded bodies, and Notion's rejected the exchange with `invalid_request: "Content-Type must be application/x-www-form-urlencoded"`. The content-type sugar now maps `:json` → `application/json`, `:form` → `application/x-www-form-urlencoded`, and passes any other string through verbatim.
- **`clj-http-native` no longer drops the last response header.** `headers-from-response` accumulated headers with a transient `assoc!` inside a `doseq`, discarding the return value — so the final header in iteration order was silently lost. This only bit responses with enough headers to expose it: Notion's `401` carried the `WWW-Authenticate` challenge as the dropped header, breaking OAuth discovery. Rebuilt as a `reduce` over the transient that keeps each `assoc!` result.
- **Boot-time OAuth device prompts are no longer swallowed by the alt-screen switch.** MCP servers that connect at startup could fire their device/verification prompt before the TUI had switched to its alternate screen buffer, so the code + URL scrolled away unseen. Boot-time prompts are now deferred behind an emit gate and flushed once the live screen is up, so the verification box always lands where you can read it.

### Added

- **`by run --resume-latest` reattaches to the newest session non-interactively.** A new flag — and the matching `BY_RESUME_LATEST` env var — resumes the most-recent persisted session (newest by last-attached-at, then started-at), falling back to a fresh session when there are none. It fills the gap between bare `--resume` (which opens the interactive stdin picker) and `--resume <id>` (which exits 1 if the id is absent): neither suits an automated relaunch. The flag is forwarded through the `--web`/`--sandbox` child launch, so a session whose process was relaunched — e.g. a hosted workspace whose container was recreated — lands back exactly where the user left off instead of in a blank session.
- **The agent's suggested follow-up persists on the input bar and shares the idle prompt with rotating help tips.** At the end of a turn the agent can emit a `next-user-prompt` — a one-line follow-up you might send next — offered on the empty input bar as a right-arrow-acceptable ghost suggestion (`↳ … (→ to use)`). It previously vanished the instant you accepted it and, while live, fully shadowed the rotating static help tips so they never showed. The suggestion now stays live until the next turn actually starts (cleared at `:agent.ask/pre`), so you can clear the input and re-summon it; accept is gated to an empty buffer so a second right-arrow can't double-append it. A new idle-tip ticker alternates the placeholder every 15s between the suggestion and a rotating static tip (`… (→ for suggestion)`) while you sit at an empty prompt — self-guarded to empty/active/no-popover, so it never repaints during a turn or while you're typing. The static tip set also grew from 4 to 16 entries covering the full `/help` command surface.

### Removed

- **The runtime `/session resume` subcommand is removed.** It was never actually implemented — the handler only listed persisted sessions or printed a `would switch to …` stub, never rehydrating any state. (The real restore path is the CLI `--resume` flag / `--resume-latest`, which are unchanged.) Typing `/session resume` now falls through to the standard `/session` usage line, and the subcommand is gone from `/help` and the `/session` autocomplete submenu. The other persisted-session subcommands (`list`, `show`, `tree`, `fork`, `label`) are unaffected.

### Fixed

- **Switching provider with `/model` no longer sends the previous provider's API key.** Hot-swapping the active LM with `/model <name>` resolved the new provider's key from a hardcoded partial env-var map that listed only OpenAI/Anthropic/Google/DeepSeek/Groq; any provider outside it (free-llm, Mistral, Together, Fireworks, OpenRouter, Azure) missed the lookup and fell back to the *current* LM's key — so switching, say, OpenAI → free-llm sent the OpenAI key as the free-llm Bearer token and the request failed with HTTP 401. The switch now reuses the current key only when the provider is unchanged, and otherwise leaves it unset so `create-lm` resolves the key from the provider catalog's own env var — matching how a fresh `by ask -p <provider>` already behaved.
- **Quitting no longer orphans background-task subprocesses.** A process started as a detached background task (e.g. `npm run dev`, which forks `sh → npm → node → next-server`) survived as a live OS process after the TUI exited — still holding its port — whether you quit via `/quit`, EOF, or double-Ctrl-C. The kill path (`cancel-task` → `:on-cancel` → `destroy-process-tree!`) and the manager's `shutdown` already existed, and the interface wrapped them as `task-shutdown`, but nothing ever called it on exit. `stop!` deliberately skipped task teardown on a false premise — that the executor's daemon worker threads let the JVM clean up — but daemon-ness only stops the JVM from *waiting* on threads; it doesn't kill `ProcessBuilder`-spawned OS processes. `stop!` now calls `task-shutdown` (covers `/quit` + EOF), and the JVM shutdown hook calls it too (covers double-Ctrl-C / SIGTERM / crash, which bypass `stop!`); the two are idempotent, so each running detached task is cancelled and its whole subprocess tree destroyed exactly once.
- **The answer box no longer breaks on tab-indented content (e.g. `git status`).** Long-form `git status` indents untracked files with a literal TAB; the answer-box layout measured width with `display-width` (which counts a TAB as one column) while the terminal expanded the TAB to a tab stop, so the right border was shoved out and the box edge went ragged on every tab-indented line. TABs in the answer are now expanded to spaces (tab stop 4) before layout, so the measured and rendered widths match and the box stays rectangular.
- **Resuming a session whose agent type is no longer registered no longer crashes.** A persisted session records its agent type; if that type isn't registered this run — a deleted user-defined agent (`user$agent$…` / a tool/hook authored then removed), a renamed/removed built-in, or a plugin agent not loaded — `create-tui-agent!` previously got an `{:error-message …}` map back from `invoke-tool` and `swap!`-ed its `nil` `:!session`, throwing an opaque `NullPointerException` that aborted the whole resume. The TUI now detects an unregistered agent type and falls back to the default `coact-agent` (with a one-line notice), so the session's conversation history still opens; a residual setup failure is surfaced as a clear error instead of a nil-`swap!` NPE.

Valid kinds: …"}` before acting, so the model retries with a valid kind. `recall` additionally errors when a `:kind` filter is given without a `:layer` (cross-layer recall ignores it). - **A turn always ends with a usable answer.** Two cases that could previously leave a turn with no answer now resolve cleanly. (1) When the iteration loop hits its cap without the model ever producing a final answer, the agent now backfills a best-effort answer from the trajectory (the latest tool result, else the latest reasoning, else a deterministic recap) instead of exiting with nothing — the loop's `:repeat` returns success on exhaustion, so the old catastrophic-failure fallback never fired for this common "ran out of iterations" case. (2) The no-action loop guard (the model reasoned but populated no channel several iterations running) now surfaces that same best-effort progress rather than a stale or empty placeholder.

Each retry now emits a muted progress line in the TUI (`⟳ Model returned an empty response — retrying (2/5)…`) instead of a silent pause. The budgets are configurable: `:max-retries-on-llm-empty-result` (**renamed** from `:empty-result-max-retries`, default raised to **5**), plus new `:max-retries-on-llm-malformed-output` (**3**) and `:max-retries-on-llm-no-action` (**3**). Anyone who set the old `:empty-result-max-retries` key must rename it — there is no legacy alias.

### Fixed

- **The abort reason survives a fatal LLM error.** When a turn aborts on an unrecoverable model error (auth / rate-limit / quota, or repeated malformed output), `:terminated-by` now reports `:llm-error` instead of being overwritten to `:answer-channel` by the terminal answer path. ### Changed

The heartbeat rides the existing detach drain pipe and self-terminates with the task; the task's `:result` is unchanged (heartbeats live only on the streaming surface).
- **Per-iteration progress trace for detached subagent tasks.** Building on the heartbeat, a detached subagent now streams a compact, meaningful trace into its task output — `[iter N/MAX] thinking…` at each iteration start and `  tool <name> → ok` / `error: …` as each tool call completes — so a polling agent watches real progress, not just a liveness tick. It works without touching the agent loop: a single built-in subscriber on the existing `:agent.iteration/pre` and `:agent.tool-use/post` events appends to the running task's output, keyed off `proto/*current-task*`. Because a subagent-as-tool runs its own loop on the future thread that carries that binding (conveyed into its `pmap` tool dispatch), its events route to the adopted task while the parent's own iterations — firing on the unbound BT thread — stay out. Observer-only and fail-open (registered under `:source :task-progress`); no-op outside a task context.
- **Structured progress snapshot in `task$detail`.** Beyond the streamed lines, `task$detail` now returns a `:progress` map for a running subagent task — `{:iteration :tools-completed :last-tool :last-tool-result :last-reasoning}` (`:last-reasoning` = the agent's latest "Think:" text) — so a polling agent can judge how far along a subagent is at a glance instead of parsing the log tail. Maintained by the same `:task-progress` hooks (iteration/tool boundaries plus the latest per-iteration observation) and evicted when the task goes terminal (`:result` then carries the final answer). Absent for non-subagent tasks.
- **Cascading cancel for subagent tasks.** Cancelling a background task that wraps a subagent (via `task$cancel`) now cancels the whole subagent chain (task → subagent → its subagents → …), not just the top future. The dispatched subagent's instance-id is captured at adoption and the task's `on-cancel` calls `runtime/cancel-run` on it, which sets the cooperative `:cancelled?` flag and aborts its in-flight LLM stream; every descendant sees it through the existing upward parent-chain `cancelled?` walk and aborts at its next BT checkpoint. Previously only the top future was interrupted, leaving descendant subagents orphaned on their own pmap threads, still burning tokens. Cancellation is cooperative — a descendant mid-LLM-call stops once that call returns. (Ctrl-C of the foreground agent already cascaded this way; this brings targeted `task$cancel` to parity.)
- **Steer a paused agent by typing (resume with a request).** While an agent's iteration loop is paused (Ctrl-\\), typing a message + Enter now resumes the *running* loop carrying that message as a mid-run steering request, instead of queueing a separate next turn. The note is folded into the loop's **active task** (`st-memory :question`, the primary objective both the react and coact loops render each iteration) as a framed directive — `[MID-RUN STEERING — you were paused and the user resumed the iteration loop with this added/updated instruction; treat it as authoritative and adjust your remaining work now] …` — so the LLM actually changes course rather than treating it as background history. Plumbed via `resume-run`'s new optional `note` arg → `[:runtime :resume-note]` → consumed at the next BT checkpoint by `apply-resume-note!` (fires whether or not the loop parked, so a pause+resume inside one LLM call still lands) → appended to `:question`. The paused banner now reads `[paused] Ctrl-\\ resume · Ctrl-C cancel · or type a message + Enter to resume with it`. (Ctrl-\\ still toggles a plain resume; Ctrl-C still cancels.)
- **Unified, generalized user-feedback mechanism.** The TUI now binds a single interactive-input primitive to each session (`:user-feedback-fn`) that dispatches on a request `:kind` — `select` (pick from 2–6 options, the historical behavior and the default), `text` (free-form line), or `confirm` (single-key choice — file-access permission uses yes/no/always/never, the last two remembered per session). Each kind renders through whichever backend is available — raw in-stream live-block, non-raw stdin, or (optionally, when feasible) a tmux popup — so the popup is just one optional backend, not a special case. File-access **permission** is now a thin adapter over this primitive (a `:confirm` request): it keeps only path normalization and its per-session approved-dir cache and delegates all prompting, collapsing the duplicate pending-state channel, lock, and raw-byte interceptor branch into one. The `get-user-feedback` tool gains a `kind` argument (`select`/`text`/`confirm`); existing positional `select` calls — `(get-user-feedback "q" ["a" "b"])` — are unchanged. A new `enable-tmux-popup` config key (default `true`) gates the popup backend — set it `false` to force every prompt to the in-stream live-block.
- **Reviewable persistence for user-defined tools & hooks.** Each definition is now saved as a human-readable pair — a pretty-printed metadata `.edn` plus a `.clj` sidecar holding the body as **verbatim** Clojure source (`#()`, regex, quotes preserved exactly; no escaping; opens with editor highlighting) — instead of a single dense one-line `.edn` with the body as an escaped string. A shared `def-store` ns handles both `tools$*` and `hooks$*`; reads still go through the safe `clojure.edn` reader and transparently fall back to the legacy single-file format, which migrates to the pair on its next overwrite.
- **`BRAINYARD_PROJECT_DIR` renamed to `BY_PROJECT_DIR`.** The project-root override env var now follows the `BY_*` convention shared by `BY_USER_ID`, `BY_WORKING_DIR`, `BY_WEB_*`, and `BY_SANDBOX_*`. Straight rename with no legacy alias — update any script or `.env` that set the old name.
